> **文档版本**: v1.0

> **对应GDD版本**: v6.1

> **v1.0核心内容**: 定义Ping系统（方向/碎片/危险）与快捷消息机制；定义冷却规则与视觉表现；定义快捷键映射。

## 一、设计背景

### 1.1 问题陈述

《双生迷城》为双人联网合作游戏，多位灾难机制高度依赖玩家间沟通：

| 灾难编号 | 名称 | 沟通需求 |
|----------|------|----------|
| V5 | 雾海入侵 | 浓雾缩小视野，需告知队友碎片位置与安全方向 |
| S1 | 幻象迷雾 | 虚假碎片幻象，需确认真实碎片位置 |
| S4 | 光线扭曲 | 碎片视觉位置与实际不符，需标记实际落点 |
| T2 | 空间折叠 | 距离关系混乱，需标注队友实际方位 |
| T4 | 镜像领域 | 视觉位置与实际不符，需协调行动方向 |

当前游戏无内置沟通工具，玩家只能依赖外部语音软件。本系统为**非语音沟通方案**，确保无语音环境下也能有效协作。

### 1.2 设计目标

1. **低干扰**：Ping标记不遮挡游戏画面，不干扰操作
2. **高效率**：快速标记，不占用建造/收集时间
3. **直观性**：颜色和图标区分Ping类型，一眼可辨
4. **防滥用**：冷却机制防止刷屏

### 1.3 设计原则

- Ping系统为**辅助沟通工具**，不替代游戏内的视觉/听觉信息
- 快捷消息覆盖最常见协作场景，不做全自由文本输入
- 所有Ping标记对**发送者和接收者均可见**
- Ping标记**不穿透UI面板**（天赋选择/暂停菜单等覆盖层激活时Ping不可用）

## 二、Ping系统

### 2.1 Ping类型

共3种Ping类型，覆盖位置标记、资源标记、危险标记三大场景。

#### 2.1.1 方向Ping

| 属性 | 值 | 说明 |
|------|-----|------|
| 功能 | 在地图上标记位置/方向 | 队友可见高亮标记 |
| 持续时间 | 3秒 | 到期自动消失 |
| 视觉表现 | 半透明白色箭头指向标记点 | 不遮挡画面 |
| 触发方式 | 鼠标中键点击地图位置 | 点击位置即为标记位置 |
| 使用场景 | 指示移动方向、标记集合点、指示碎片密集区 |

#### 2.1.2 碎片Ping

| 属性 | 值 | 说明 |
|------|-----|------|
| 功能 | 标记碎片落点 | 队友可见金色高亮箭头指向 |
| 持续时间 | 5秒 | 碎片存续时间3.5秒，留出反应余量 |
| 视觉表现 | 半透明金色向下箭头 + 碎片图标 | 落点正上方显示 |
| 触发方式 | 鼠标中键点击碎片/碎片落点 | 点击碎片或预判落点均可 |
| 使用场景 | 标记高价值碎片、V5雾海/S4光线扭曲下标记真实碎片位置 |

#### 2.1.3 危险Ping

| 属性 | 值 | 说明 |
|------|-----|------|
| 功能 | 标记危险区域 | 队友可见红色警告圈 |
| 持续时间 | 3秒 | 到期自动消失 |
| 视觉表现 | 半透明红色圆圈（半径2格）+ 闪烁边框 | 不遮挡但高警示性 |
| 触发方式 | Ctrl + 鼠标中键点击 | 组合键避免误触 |
| 使用场景 | 标记熔岩蔓延区、坑洞位置、碎片掉落危险区 |

### 2.2 Ping颜色编码

| Ping类型 | 颜色 | RGB参考值 | 语义 |
|----------|------|-----------|------|
| 方向Ping | 白色 | rgba(255,255,255,0.5) | 中性信息 |
| 碎片Ping | 金色 | rgba(255,200,50,0.5) | 资源信息 |
| 危险Ping | 红色 | rgba(255,60,60,0.4) | 警示信息 |

> **设计说明**：所有Ping均使用半透明颜色（alpha 0.4-0.5），确保不遮挡游戏画面中的碎片、建筑、角色等关键元素。颜色编码与游戏内已有颜色系统一致——金色用于资源（温砖为金色），红色用于危险（HP扣血提示为红色）。

### 2.3 Ping冷却机制

| 规则 | 数值 | 说明 |
|------|------|------|
| 单次Ping冷却 | 2秒 | 发出1次Ping后2秒内不可再次Ping |
| 冷却共享 | 3种Ping类型共享冷却 | 防止交替使用绕过冷却 |
| 冷却视觉 | 冷却中鼠标光标变灰 | 玩家可见冷却状态 |
| 冷却中尝试Ping | 无视觉效果 + 轻微"咔"音效 | 反馈操作无效但不打断节奏 |

> **设计说明**：2秒冷却为 ⚠️ 待原型测试值。目标是在"防止刷屏"与"不影响紧急沟通"之间取得平衡。若测试中发现紧急情况下2秒冷却影响体验，可降至1.5秒。

## 三、快捷消息系统

### 3.1 预设消息列表

共8条预设快捷消息，覆盖合作游戏中最常见的沟通场景：

| 编号 | 快捷键 | 消息内容 | 使用场景 |
|------|--------|----------|----------|
| 1 | Tab+1 | "去左边" | 指示移动方向 |
| 2 | Tab+2 | "去右边" | 指示移动方向 |
| 3 | Tab+3 | "回来" | 召回队友到安全区/庇护范围 |
| 4 | Tab+4 | "需要保护" | 请求队友靠近维持庇护 |
| 5 | Tab+5 | "跟我走" | 引导队友跟随 |
| 6 | Tab+6 | "危险" | 通用危险警告 |
| 7 | Tab+7 | "快捡碎片" | 提醒碎片即将消失 |
| 8 | Tab+8 | "合成台集合" | 召集队友到合成台 |

### 3.2 快捷消息表现

| 属性 | 说明 |
|------|------|
| 显示位置 | 角色头顶气泡 |
| 气泡样式 | 圆角矩形 + 角色对应颜色边框（水人蓝色/火人橙色） |
| 持续时间 | 3秒后自动消失 |
| 字体 | 18px白色加粗，黑色描边 |
| 多消息叠加 | 同一角色3秒内发送多条消息时，仅显示最新一条 |

### 3.3 快捷消息与Ping的关系

| 维度 | 快捷消息 | Ping |
|------|----------|------|
| 信息类型 | 文字语义（做什么） | 空间位置（在哪里） |
| 触发方式 | Tab+数字键 | 鼠标中键 |
| 冷却 | 无独立冷却（受Ping冷却约束） | 2秒冷却 |
| 显示位置 | 角色头顶气泡 | 地图标记 |

> **设计说明**：快捷消息发送时也会触发Ping冷却（2秒），因为快捷消息本质上也是一种沟通行为。这防止玩家同时刷Ping和快捷消息。⚠️ 待原型测试：是否需要对快捷消息单独设冷却。

## 四、快捷键设计

### 4.1 快捷键映射表

| 操作 | 快捷键 | 说明 |
|------|--------|------|
| 方向Ping | 鼠标中键点击 | 点击位置即为标记位置 |
| 碎片Ping | 鼠标中键点击碎片/碎片落点 | 自动识别目标为碎片时切换为碎片Ping |
| 危险Ping | Ctrl + 鼠标中键点击 | 组合键，避免误触 |
| 快捷消息1-8 | Tab + 数字键1-8 | 按住Tab后按数字键 |

### 4.2 Ping类型自动识别规则

鼠标中键点击时，系统根据点击目标自动判断Ping类型：

```
点击目标判断逻辑：
├── 点击位置有碎片/碎片落点 → 碎片Ping（金色）
├── Ctrl按住 → 危险Ping（红色）
└── 其他 → 方向Ping（白色）
```

> **设计说明**：自动识别减少了玩家记忆负担。玩家只需"鼠标中键点哪里就Ping哪里"，系统智能判断类型。Ctrl+中键为手动覆盖（强制危险Ping）。

### 4.3 快捷键冲突检查

| 系统已有按键 | 沟通系统按键 | 冲突分析 |
|-------------|-------------|----------|
| E键（技能） | 无冲突 | 沟通系统不使用E/Q |
| Q键（技能） | 无冲突 | 沟通系统不使用E/Q |
| 空格键（跳跃） | 无冲突 | 沟通系统不使用空格 |
| WASD（移动） | 无冲突 | 沟通系统不使用WASD |
| 1-8数字键 | Tab+数字键 | 单独按数字键无功能，需配合Tab |

> **设计说明**：Tab键在多数游戏中用于查看记分板/菜单，但本作为双人合作PvE游戏无记分板需求。Tab+数字键的组合方式不与任何现有操作冲突。🔲 待讨论：是否需要在天赋选择阶段（15秒升级阶段）禁用Tab快捷消息，避免与天赋卡片选择（数字键1-3选牌）冲突。

## 五、视觉表现规范

### 5.1 Ping标记视觉层级

Ping标记位于游戏画面**最上层**，但低于以下UI元素：

| 层级 | 元素 | 说明 |
|------|------|------|
| 底层 | 游戏场景（地图/建筑/角色） | 正常渲染 |
| 中层 | 碎片/灾难特效 | 正常渲染 |
| 上层 | Ping标记 | 半透明叠加 |
| 顶层 | HUD/UI面板 | 始终最前 |

### 5.2 Ping标记动画

| Ping类型 | 出现动画 | 消失动画 |
|----------|----------|----------|
| 方向Ping | 从标记点向外扩散1次波纹（0.3秒） | 渐隐淡出（0.3秒） |
| 碎片Ping | 金色箭头从上方滑入（0.2秒） | 渐隐淡出（0.3秒） |
| 危险Ping | 红色圆圈从0.5倍缩放至1.0倍（0.2秒）+ 边框闪烁2次 | 渐隐淡出（0.3秒） |

### 5.3 快捷消息气泡样式

```
┌─────────────────┐
│   快捡碎片！     │  ← 18px白色加粗，黑色描边
└────────┬────────┘
         │           ← 气泡尾巴指向角色
    [角色头像]
```

- 气泡圆角半径：8px
- 边框颜色：水人 rgba(60,150,255,0.8) / 火人 rgba(255,140,40,0.8)
- 背景：rgba(20,20,30,0.85)
- 最大宽度：200px（消息文本不换行，超出则自动缩小字号至14px）

## 六、灾难联动设计

### 6.1 沟通系统在特定灾难中的价值

| 灾难 | 沟通痛点 | Ping应对方案 |
|------|----------|-------------|
| V5 雾海入侵 | 视野缩小至10%，看不到远处碎片 | 碎片Ping穿透雾气可见（金色高亮在雾中更醒目） |
| S1 幻象迷雾 | 虚假碎片幻象无法区分 | 碎片Ping仅对真实碎片生效（系统自动识别） |
| S4 光线扭曲 | 碎片视觉位置与实际不符 | 碎片Ping标记实际位置（金色箭头指向真实落点） |
| T2 空间折叠 | 距离关系混乱 | 方向Ping标记实际坐标（不受空间折叠影响） |
| T4 镜像领域 | 视觉位置镜像 | 方向Ping标记真实方位（Ping坐标不受镜像影响） |

### 6.2 Ping穿透规则

| 灾难效果 | Ping是否受影响 | 说明 |
|----------|---------------|------|
| 雾海（视野缩小） | 不受影响 | Ping标记在雾中仍可见，作为"穿透雾气的信标" |
| 幻象（虚假碎片） | 碎片Ping仅标记真实碎片 | 系统自动区分真伪 |
| 光线扭曲 | 不受影响 | Ping标记实际坐标 |
| 空间折叠 | 不受影响 | Ping标记实际坐标 |
| 镜像领域 | 不受影响 | Ping标记实际方位 |

> **设计说明**：Ping系统作为"沟通工具"而非"游戏内视觉元素"，其坐标和显示不受灾难的视觉干扰效果影响。这是设计意图——沟通系统帮助玩家克服灾难带来的信息缺失，而不是被灾难一同干扰。⚠️ 待原型测试：Ping穿透所有视觉干扰是否过于强力，是否需要部分灾难（如S2声波干扰）同时屏蔽Ping系统。

## 七、技术实现要点

### 7.1 网络同步

| 要素 | 同步方式 | 说明 |
|------|----------|------|
| Ping位置 | 即时同步 | 发送者点击后立即广播给接收者 |
| Ping类型 | 随位置一起同步 | 3种类型共用同一同步消息 |
| Ping持续时间 | 接收者本地计时 | 发送时同步时间戳，接收者按本地时间倒计时 |
| 快捷消息 | 即时同步 | 发送后立即在接收者画面显示气泡 |
| 冷却状态 | 本地管理 | 冷却不需网络同步，各自本地计时 |

### 7.2 性能考量

- Ping标记为轻量UI元素（半透明Sprite/纹理），不涉及物理碰撞
- 同屏同时存在的Ping标记上限：**每玩家3个**（超过时最早的自动消失）
- 快捷消息气泡同时存在上限：**每玩家1个**（新消息覆盖旧消息）
