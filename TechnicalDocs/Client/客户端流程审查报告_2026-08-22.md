> **审查日期**: 2026-08-22
> **审查范围**: Client/Assets/Scripts/ 全部 166 个 C# 文件的流程逻辑（重点：单局流程闭环、联机同步流程、UI 流程），并对照 Server/game-server 与《状态同步实施计划.md》

## 二、🔴 P0 — 核心玩法循环断链（按对局时间线排列）

### A. 碎片接住后进不了背包（整条经济链的源头断裂）
- **位置**: `Fragment/FragmentSystem.cs`（发布 `FragmentCollectedEvent`）、`Character/CharacterController.cs L142 AddFragment`
- **现象**: `FragmentCollectedEvent` 的订阅者只有 `NetworkGameSync`（上报服务器）。**没有任何订阅者调用 `CharacterController.AddFragment` 把碎片加入 `CarriedFragmentIds`**。全库 `AddFragment` 的唯一调用方是 `SynthesisSystem.InterruptSynthesis`（打断返还）。
- **后果链**:
  1. HUD 碎片计数永远显示 `冰×0 熔岩×0 岩石×0`（`UIGameHudCtrl.RefreshFragmentCount` 读 `CarriedFragmentIds`）；
  2. `SynthesisSystem.TryStartSynthesis` 因 `carriedCount=0` 永远失败；
  3. 服务器侧 `carriedFragments` 记账正确，`S2C_MidFreqState` 已携带 `carriedFragments int[]`，但客户端 `GameServerClient` 解析后**丢弃不用**——权威数据通道是通的，客户端没接。
- **修复方向**: 联机模式以 `S2C_MidFreqState.carriedFragments` 为权威写入背包；本地判定仅作过渡。顺带处理倍率：`multiplier ×2/×3`（跳跃/同接）字段全链路无消费者，服务器同接是"双方各 +2"，客户端需对齐。

### B. 合成无入口 + 产出无人接收
- **位置**: `Synthesis/SynthesisSystem.cs`（`TryStartSynthesis` 全库无调用方；`MaterialProducedEvent` 无订阅者）
- **现象**: 没有任何 UI/输入调用开始合成；即使合成完成，`CharacterController.AddMaterial` 也无人调用（唯一调用方是 `BuildingSystem.DemolishBuildingCoroutine` 拆除返还）。
- **后果**: 玩家永远持有 0 材料 → 建造无从谈起。`SynthesisStation`（排队/占用）同样无调用方，纯死代码。

### C. 建造全链路无入口、无视觉
- **位置**: `Building/BuildingSystem.cs`
- **无调用方的方法**: `GenerateBlueprint`、`PlaceBuilding`、`RepairBuilding`、`DemolishBuilding`、`SetSafeZone`、`SetDisasterDirection`、`SyncBuildingHPs`
- **附加问题**: `PlaceBuildingCoroutine` 只写 `BuildingData` 入列表，**不实例化任何 GameObject**；`BuildingPlacedEvent` 仅 `ShelterSystem` 订阅 → 即使放了建筑玩家也看不见。
- **后果**: 蓝图不生成、不能建造、看不见建筑。预告阶段"显示建筑蓝图"（GDD §流程）完全缺失。

### D. 灾害从不启动（单机/联机均如此）
- **位置**: `Disaster/DisasterSystem.cs`（`StartDisaster` 全库无调用方）；Server `GameManager.onPhaseEnter` 仅处理 `Preview`，注释"灾难模拟在对应里程碑接入"
- **现象**: 客户端 35 种灾害实现（E1-E8/V1-V6/T1-T5/S1-S5/P1-P5/M1-M6 共 34 个子类）全部为死代码；`DisasterImpact` 阶段 20 秒内什么都不会发生。
- **后果链（重要）**: `ShelterSystem.CurrentEnvironment` 永远是默认 `Normal` → `GetEnvironmentDamageRate` 走 default 返回 0 → 即使能量耗尽也**不扣血**；`SetEnvironment` 的唯一潜在调用来源是灾害系统。⇒ **当前版本玩家不可能死亡**。

### E. 胜负判定永不触发（联机死局）
- **位置**: 客户端 `Shelter/ShelterSystem.cs`（发布 `PlayerDiedEvent`，注释写"触发游戏结束"但**全库无订阅者**）；Server `GameStateMachine.nextPhase`（36 轮跑完仅 `stop()`，**不广播任何结束消息**）
- **后果**:
  1. 死亡路径断（当前被 D 掩盖，D 修复后立刻暴露）；
  2. 通关路径断：服务器状态机停止后不再发 `S2C_PhaseChange`，客户端 `ApplyServerPhase` 等待模式下倒计时归零后**永远卡在最后的 Upgrade 阶段**，无结算、无返回；
  3. `GameManager.EndGame` 正常对局中无任何触发方（仅 UIGameOver 重开和无人调用的 `AdvanceToNextLevel`）。
- **修复方向**: 服务器 36 轮完成/玩家死亡时广播 `S2C_GameEnd`，客户端订阅后调 `GameManager.EndGame`；服务器房间在 `isExpired` 前先通知。

### F. 关卡进度双端都不推进
- **位置**: 客户端 `GameManager.AdvanceToNextLevel` 无调用方；`S2C_GameStart` 的 chapter/section/round 被 `UIHomeCtrl/UIRoomCtrl` 的 `OnGameStart(RoomGameStartEvent e)` **直接忽略**（参数 e 未用）
- **后果**: HUD 永远显示"第1章 1-1 · 第1轮"；`GameProgress.DifficultyMultiplier` 永远 0.8；`ShelterSystem` 章末恢复（GlobalRound%12==0）永不触发。
- **修复方向**: 服务器每轮 Preview 广播进度（或复用 PhaseChange 携带），客户端写入 `GameManager.State.Progress` 并同步 `FragmentSystem.SetCurrentRound`（该方法同样无调用方，存续时间永远按第 1 轮算）。

### G. 掉落计划协程不可取消
- **位置**: `Fragment/FragmentSystem.cs ExecuteDropPlanCoroutine`
- **现象**: `StartCoroutine` 无任何停止机制。对局中退出（`ExitToHome`）、自然结束、新一轮计划到达时，旧协程继续按计划掉碎片（FragmentSystem 是 DontDestroyOnLoad 单例，跨对局存活）；`ClearPool` 也不停协程；新一轮 `S2C_FragmentDropPlan` 到达时新旧两个协程并行。
- **同类问题**: `BuildingSystem` 的放置/修补/拆除协程在 `State.IsGameOver` 后依然会执行。
- **修复方向**: 记录协程引用，`GameEndEvent`/新计划到达时 `StopCoroutine`；协程体内检查 `IsRunning`。

### H. 单机模式是空壳但 UI 仍放出入口
- **位置**: `UIHomeCtrl` 未连接即可点"开始游戏"→ `GameManager.StartGame()` 单机分支；`UIGameOverCtrl` 的"再来一局"按钮仅单机可用
- **现象**: 单机开局后 7 阶段空转：无碎片（`GenerateDropPlan` 无调用方）、无蓝图、无灾害、无进度（F）、无胜负（E）→ "再来一局"循环空局。
- **建议**: 明确单机定位（开发调试 or 玩法模式）。若保留调试用途，至少接入本地掉落+灾害+死亡判定，否则隐藏入口。

## 三、🟠 P1 — 联机流程 Bug

### I. 主动退出对局后网络状态残留，用户被卡死
- **位置**: `Network/GameServerClient.cs Disconnect()`、`Core/GameManager.cs ExitToHome()`、`UIHomeCtrl.OnShow`
- **链路**: `ExitToHome` → `GameServerClient.Disconnect()`（`_disconnectPublished=true`，**不发布** `ServerDisconnectedEvent`）→ `Cleanup()` 只清自己的 `IsConnected`。**`NetworkSystem.IsConnected` 保持 true、`CurrentRoomCode` 残留、`UIHomeCtrl._playerCount` 残留**。
- **后果**: 回主界面 `OnShow` 检测到 roomCode 非空 → `_roomReady=true` → 显示旧房间码"等待好友加入..."；点开始 → `RequestStartGame` 因 `GameServerClient.IsConnected=false` 只打一行 warning，UI 无任何反馈 → 死局，无法再建房（只能重启）。
- **修复方向**: `Disconnect()` 统一走 `NetworkSystem.SetConnected(false)+SetRoomCode("")`；或 `ExitToHome` 断开后调用 `UIHomeCtrl.ResetRoomUi` 等价逻辑。注意 `UIRoomCtrl.OnLeaveClicked` 是手动补了 `SetRoomCode("")` 的，说明此坑曾被局部修过。

### J. 加入房间失败无任何反馈（客户端挂起）
- **位置**: Server `RoomManager.onPlayerConnect`（房间不存在/已满/已开局 → 仅 log.warn 返回）；Client `GameServerClient.Connect`
- **现象**: WebSocket 握手成功但进房失败时客户端收不到任何消息，`RoomConnectedEvent` 永不触发，无超时兜底（5s 超时只覆盖握手）。受邀方接受邀请后界面毫无反应。
- **修复方向**: 服务器回 `S2C_JoinFailed{reason}`；客户端 `Connect` 增加进房 Ack 超时（如 5s）提示失败。

### K. 断线重连为死代码且入口被堵
- **位置**: Server `GameRoom.onPlayerReconnect`（快照生成后**直接丢弃**，TODO 未发）；`RoomManager.onPlayerConnect` 对 `isGameStarted()` 房间直接拒绝 → `onPlayerReconnect` 无任何调用方
- **现象**: 对局中断线后重连（按房间码）会被当成普通进房拒绝；对方 HUD 横幅"对方连接中断"永不消失，服务器对局继续空跑到 36 轮。
- **属计划内**（M5 断线重连），但建议先做最小闭环：重连至少恢复阶段/位置，或超时后服务器广播结束。

### L. 双人本地模拟 + 服务器快照双轨打架（过渡架构风险）
- **位置**: `ShelterSystem.OnUpdate` 联机下仍模拟双方能量/扣血并对**远程角色**发 `PlayerDamagedEvent`；HUD 又用 `NetworkSystem.OpponentHP`（服务器 10Hz）覆盖显示
- **现象**: 服务器 `updatePlayerHighFreq` 的 HP/能量来源就是客户端上报——即"对手数值 = 对手上报的本地模拟"，往返一圈；本地对远程角色的模拟结果与对手上报值可能跳变。`PlayerDiedEvent`/技能减伤等以本地 ShelterSystem 为准，与对手端可能不一致。
- **属计划内**（M5 服务器权威），列为风险提醒：在 M5 落地前，联机下 ShelterSystem 应只模拟本地角色。

## 四、🟡 P2 — 逻辑缺陷

### M. 网格坐标 ↔ 世界坐标错位（两处，互相独立且都致命）
- **M1** `BuildingSystem.IsCharacterInSafeZone`: 安全区中心用网格坐标 `(7,4)` 直接当世界坐标与角色世界坐标比距离。实际安全区世界中心约 `(0,-4)` → 距离恒 ≈10.6 > 半径 5 → **恒 false** → "两人均在安全区才能建造"永远不满足（C 修复后会立刻暴露）。
- **M2** `ShelterSystem.IsInBuildingZone`: `Vector2.Distance(worldPos, new Vector2(gridPos.x, gridPos.y))` 同样把建筑格子坐标当世界坐标 → 恒 > 2.5 → **灾害期间建筑区域保护永远不生效**（若 D 修复后暴露）。
- **修复方向**: 定义统一换算（参考 `MapLoader`: 网格 15×8 世界中心 (0,-4) → `world = gridPos - new Vector2Int(7,4)` + 偏移），两处 + 蓝图渲染共用。

### N. 联机非确定性随机源
- `FragmentSystem.CheckPassiveSkills` 用 `UnityEngine.Random`（寒霜/烈焰体质触发）→ 双端各自掷骰，冻结/点燃/温砖转换可能只在一端发生；
- `BuildingSystem.GenerateBlueprint` 全程 `Random.Range`（形状/M4 材料/Mechanism 环境）→ 若未来 Host 生成蓝图需同步，必须改种子化。
- 服务器掉落计划已带 per-fragment seed 但客户端未消费（`FragmentDropPlan.Seed` 传入 `Initialize` 后无人使用）。

### O. 地震冲击波计时器被双角色共享
- `ShelterSystem._earthquakeShockwaveTimer` 在同帧被 Aqua/Ignis 两次 `UpdateBufferAndDamage` 各加一次 dt → 双人都暴露时冲击波间隔减半（2s→1s）。应按角色分开或只累计一次。

### P. `PopTo<UIHomeCtrl>` 未命中目标时清空整个面板栈
- `UIManager.PopTo` while 循环弹到栈空才 warning。`ExitToHome` 场景下若栈里没有 UIHome（如从测试路径开局），所有面板被弹出且不恢复 → 黑屏无路可走。建议未命中时保留栈并返回 false。

### Q. `UIRoomCtrl` 死代码与 `UIHomeCtrl` 双订阅同事件
- 两者都订阅 `RoomGameStartEvent` 且都调 `SetPanelsVisible(false)+StartGame()`。当前 UIRoom 无 Push 方向（已停用）暂无实害，但一旦有人复用（`Prepare+Push`）即双触发 `StartGame`（`RebuildForNetwork`×2、`GameStartEvent`×2）。建议删除 UIRoom 或在其中移除开局逻辑。

### R. `GameLaunch` 重复 AudioListener
- `Awake` 中 listeners==0 时给自身 GameObject 加一个；随后 `EnsureCamera` 新建 MainCamera 时又 `AddComponent<AudioListener>` → 2 个监听器告警。另：运行时 `Awake` 用 `DestroyImmediate` 不推荐（应 `Destroy`）。

### S. `GameManager.Update` 无"对局进行中"守卫
- 登录/主界面阶段 Shelter/Synthesis/Skill/Disaster 已每帧更新（当前因 phase=Preview 无实际危害）。建议以 `GameStartEvent/GameEndEvent` 或 `State.IsInGame` 收口，避免未来 Preview 阶段逻辑（蓝图生成等）在登录界面误触发。

## 六、修复优先级建议

1. **先打通经济链最小闭环**（A→B→C 建造入口与视觉 + M 坐标修复）：这是"游戏"成立的前提，联机同步协议可复用现有 MidFreq 通道。
2. **胜负闭环**（E：S2C_GameEnd + PlayerDiedEvent 订阅；D：灾害接入 DisasterImpact + SetEnvironment）——否则测试 1 时玩家无敌，建造压力无法验证。
3. **联机体验 Bug**（I 状态残留、J 无反馈、G 协程取消）——都是小改动大收益。
4. **F 进度推进、N 确定性、L 双轨收敛**——随 M5 服务器权威化一并处理。
5. P2/P3 择机清理（Q/R/S 建议尽快，改动小）。
