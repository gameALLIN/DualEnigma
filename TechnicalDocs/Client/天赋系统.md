## 一、系统概述

### 1.1 系统职责

天赋系统负责：
- 53个天赋池管理（水人18 + 火人18 + 共享17）
- 每轮升级阶段3选1选择机制
- 稀有度随章节递进概率
- 保底与追赶机制（史诗保底/稀有提升/HP追赶）
- 天赋效果叠加与封顶规则

### 1.2 在整体架构中的位置

```
Core（EventBus / ServiceLocator）
         │
    TalentSystem
    │           │
    ├── 天赋池管理（53个天赋，按角色+稀有度索引）
    ├── 卡牌发放（3选1，按章节稀有度概率）
    ├── 保底机制（史诗保底/稀有提升计数器）
    ├── HP追赶（濒死保护/章节恢复/急救保底）
    └── 效果叠加（线性叠加/百分比封顶）
              │
     依赖：CharacterSystem / SkillSystem / ShelterSystem
```

### 1.3 依赖关系

| 依赖方向 | 说明 |
|----------|------|
| Talent → Core | EventBus / ServiceLocator |
| Talent → Character | 修改角色属性（HP/移速/搬运上限等） |
| Talent → Skill | 修改技能属性（冷却/范围/护盾等） |
| Talent → Shelter | 修改庇护参数（能量/距离/扣血等） |
| Network → Talent | 天赋选择结果同步 |

## 二、数据结构

### 2.1 天赋数据结构

```csharp
namespace DualEnigma.Talent
{
    /// <summary>
    /// 天赋目标类型
    /// </summary>
    public enum TalentTarget
    {
        /// <summary>水人专属</summary>
        Aqua,
        /// <summary>火人专属</summary>
        Ignis,
        /// <summary>共享</summary>
        Shared,
    }

    /// <summary>
    /// 天赋效果类型
    /// </summary>
    public enum TalentEffectType
    {
        /// <summary>数值叠加类（HP+20、能量+30等）</summary>
        NumericAdd,
        /// <summary>百分比类（冷却-20%、范围+30%等）</summary>
        PercentageModify,
        /// <summary>机制改变类（双重释放等）</summary>
        MechanismChange,
        /// <summary>条件触发类（HP<30%时触发等）</summary>
        ConditionalTrigger,
    }

    /// <summary>
    /// 天赋数据。
    /// 引用：天赋系统设计.md §三/四/五 天赋池
    /// </summary>
    [System.Serializable]
    public class TalentData
    {
        /// <summary>天赋ID</summary>
        public int Id;
        /// <summary>天赋名称</summary>
        public string Name;
        /// <summary>稀有度</summary>
        public Rarity Rarity;
        /// <summary>目标类型</summary>
        public TalentTarget TargetType;
        /// <summary>效果类型</summary>
        public TalentEffectType EffectType;
        /// <summary>效果值</summary>
        public float EffectValue;
        /// <summary>效果描述</summary>
        public string Description;
        /// <summary>是否可叠加</summary>
        public bool Stackable;
        /// <summary>最大叠加次数（0=无上限）</summary>
        public int MaxStacks;
    }
}
```

## 三、核心接口与类设计

### 3.1 TalentSystem

```csharp
namespace DualEnigma.Talent
{
    /// <summary>
    /// 天赋系统管理器。继承 Singleton<T>，注册 ITalentSystem 到 ServiceLocator。
    /// </summary>
    public class TalentSystem : Singleton<TalentSystem>, ITalentSystem
    {
        /// <summary>水人已选天赋列表</summary>
        public List<TalentData> AquaTalents { get; }
        /// <summary>火人已选天赋列表</summary>
        public List<TalentData> IgnisTalents { get; }

        /// <summary>发放3个天赋供选择（升级阶段调用）</summary>
        /// <param name="owner">角色类型</param>
        /// <param name="chapter">当前章节（1-3，决定稀有度概率）</param>
        /// <returns>3个天赋</returns>
        public List<TalentData> DrawTalents(CharacterType owner, int chapter);

        /// <summary>选择天赋</summary>
        public void SelectTalent(CharacterType owner, int talentId);

        /// <summary>获取已选天赋的叠加效果</summary>
        /// <param name="owner">角色类型</param>
        /// <returns>叠加后的效果汇总</returns>
        public TalentEffectSummary GetEffectSummary(CharacterType owner);
    }

    public interface ITalentSystem
    {
        List<TalentData> AquaTalents { get; }
        List<TalentData> IgnisTalents { get; }
        void SelectTalent(CharacterType owner, int talentId);
    }

    /// <summary>
    /// 天赋效果汇总
    /// </summary>
    [System.Serializable]
    public class TalentEffectSummary
    {
        /// <summary>HP加成</summary>
        public int HPBonus;
        /// <summary>能量最大值加成</summary>
        public float EnergyMaxBonus;
        /// <summary>能量恢复速率乘数</summary>
        public float EnergyRecoveryMultiplier = 1f;
        /// <summary>庇护距离加成（格）</summary>
        public float ShelterDistanceBonus;
        /// <summary>扣血速率乘数</summary>
        public float DamageMultiplier = 1f;
        /// <summary>冷却缩短（0-0.8）</summary>
        public float CooldownReduction;
        /// <summary>技能范围乘数</summary>
        public float RangeMultiplier = 1f;
        /// <summary>搬运上限加成</summary>
        public int CarryLimitBonus;
        /// <summary>移速乘数</summary>
        public float MoveSpeedMultiplier = 1f;
        /// <summary>被动触发概率加成</summary>
        public float PassiveChanceBonus;
        /// <summary>是否可双重释放</summary>
        public bool CanDoubleRelease;
    }
}
```

## 四、详细逻辑

### 4.1 选择机制

**选择时机**：每轮灾害结束后的升级阶段（15秒），3选1。

**选择频次**：

| 层级 | 次数 |
|------|------|
| 每轮 | 1次 |
| 每节 | 3次 |
| 每章 | 12次 |
| 全游戏 | 36次 |

### 4.2 稀有度随章节递进

| 章节 | 普通（★） | 稀有（★★） | 史诗（★★★） |
|------|-----------|------------|-------------|
| 第一章 | 75% | 20% | 5% |
| 第二章 | 55% | 35% | 10% |
| 第三章 | 40% | 40% | 20% |

### 4.3 保底与追赶机制

> 引用：天赋系统设计.md §2.7

**史诗保底**：
- 每章12轮中，若选择第12轮天赋前未获得任何史诗(★★★)天赋
- 则第12轮的3选1中保证至少包含1个史诗天赋
- 若已获得过史诗天赋，则按正常概率发放

**稀有提升**：
- 系统维护"未获得稀有+计数器"
- 每轮3选1中若无稀有(★★)以上天赋，计数器+1
- 计数器达到3时，下一轮3选1中至少包含1个稀有(★★)以上天赋
- 所有普通(★)天赋的稀有度提升一级
- 一旦玩家选择稀有(★★)以上天赋，计数器归零

**HP追赶机制**：

| 规则 | 说明 |
|------|------|
| 濒死保护 | HP≤30%时，环境扣血速率临时降低30% |
| 章节恢复 | 每章结束（第12/24/36轮）恢复15HP |
| 急救保底 | 全游戏至少出现2次"急救"天赋（★★稀有）可选 |

### 4.4 叠加规则

| 天赋类型 | 叠加方式 | 上限 |
|----------|----------|------|
| 数值加成类 | 线性叠加 | 无上限 |
| 百分比加成类 | 线性叠加 | 效果封顶 |
| 机制改变类 | 不叠加 | 最多1次 |

**百分比封顶规则**：

| 效果 | 封顶值 | 说明 |
|------|--------|------|
| 冷却缩短 | -80% | 保留20%基础冷却 |
| 扣血减缓 | -90% | 保留10%基础扣血 |
| 移速增加 | +100% | 移速翻倍上限 |
| 能量恢复 | +200% | 恢复速率×3上限 |

### 4.5 期望分布统计

> 引用：天赋系统设计.md §8.5

| 章节 | 轮次 | 期望普通 | 期望稀有 | 期望史诗 |
|------|------|----------|----------|----------|
| 第一章 | 12 | 9.0 | 2.4 | 0.6 |
| 第二章 | 12 | 6.6 | 4.2 | 1.2 |
| 第三章 | 12 | 4.8 | 4.8 | 2.4 |
| **全游戏** | **36** | **20.4** | **11.4** | **4.2** |

验证结论：全游戏期望史诗天赋4.2个，足以支撑1-2个核心Build成型。
