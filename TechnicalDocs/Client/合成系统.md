## 一、系统概述

### 1.1 系统职责

合成系统负责：
- 合成台交互逻辑（站台上按住交互键）
- 根据当前灾害庇护环境匹配合成配方
- 碎片消耗与材料产出
- 合成中打断处理（碎片返还）

### 1.2 在整体架构中的位置

```
Core（EventBus / ServiceLocator）
         │
    SynthesisSystem
    │           │
    ├── 合成台交互检测
    ├── 配方匹配（按庇护环境索引）
    ├── 合成计时（1秒 / 1.5秒 / 2秒）
    └── 材料产出通知
              │
     依赖：FragmentSystem / BuildingSystem
```

### 1.3 依赖关系

| 依赖方向 | 说明 |
|----------|------|
| Synthesis → Core | EventBus / ServiceLocator |
| Synthesis → Fragment | 消耗角色携带的碎片 |
| Synthesis → Building | 产出的材料供建造使用 |
| Character → Synthesis | 角色站在合成台上触发合成 |

## 三、核心接口与类设计

### 3.1 SynthesisSystem

```csharp
namespace DualEnigma.Synthesis
{
    /// <summary>
    /// 合成系统管理器。继承 Singleton<T>，注册 ISynthesisSystem 到 ServiceLocator。
    /// </summary>
    public class SynthesisSystem : Singleton<SynthesisSystem>, ISynthesisSystem
    {
        /// <summary>当前庇护环境对应的合成表</summary>
        public List<SynthesisRecipe> CurrentRecipes { get; }

        /// <summary>设置当前庇护环境（阶段切换时调用）</summary>
        /// <param name="environment">庇护环境类型</param>
        public void SetEnvironment(ShelterEnvironment environment);

        /// <summary>尝试开始合成</summary>
        /// <param name="playerId">操作玩家</param>
        /// <param name="fragmentType">选择的碎片类型</param>
        /// <param name="desiredOutput">期望产出的材料类型</param>
        /// <returns>匹配到的配方，无匹配或碎片不足返回 null</returns>
        public SynthesisRecipe? TryStartSynthesis(byte playerId, FragmentType fragmentType, MaterialType desiredOutput);

        /// <summary>合成进度更新</summary>
        /// <returns>0-1 的进度值</returns>
        public float GetSynthesisProgress(byte playerId);

        /// <summary>打断合成（移动或被击中时调用）</summary>
        public void InterruptSynthesis(byte playerId);
    }

    public interface ISynthesisSystem
    {
        List<SynthesisRecipe> CurrentRecipes { get; }
        void SetEnvironment(ShelterEnvironment environment);
        SynthesisRecipe? TryStartSynthesis(byte playerId, FragmentType fragmentType, MaterialType desiredOutput);
        float GetSynthesisProgress(byte playerId);
        void InterruptSynthesis(byte playerId);
    }
}
```

## 四、详细逻辑

### 4.1 合成台

| 属性 | 说明 |
|------|------|
| 位置 | 建筑区域内中心 |
| 数量 | 轮次1-2有两台，轮次3减为1台 |
| 交互方式 | 站在合成台上，按住交互键 |
| 队列规则 | 两人同时使用需排队 |
| 打断规则 | 移动或被击中则中断，碎片返还 |

### 4.2 合成流程

```
角色站在合成台上
    → 按住交互键
        → SynthesisSystem.TryStartSynthesis(playerId, fragmentType)
            → 匹配当前环境合成表
                ├── 匹配成功 → 检查携带碎片数量
                │   ├── 数量足够 → 消耗碎片，启动合成计时
                │   │   → 计时完成 → 产出材料
                │   │   → EventBus.Publish(new MaterialProducedEvent { ... })
                │   └── 数量不足 → 提示"碎片不足"
                └── 无匹配 → 提示"当前环境无法合成"
    → 合成中角色移动/被击中
        → InterruptSynthesis(playerId) → 碎片返还
```

### 4.3 配方匹配

**匹配逻辑**：根据当前庇护环境索引合成表，按碎片类型查找配方。

```
当前庇护环境 = 火山
合成表 = 火山环境配方

冰晶碎片 → 匹配到:
    水砖 (冰晶×2, 1s) — 基础配方
    冰砖 (冰晶×3, 1.5s) — 高级配方

玩家选择：
    携带2个冰晶 → 可选水砖
    携带3个冰晶 → 可选水砖或冰砖
```

### 4.4 M4预言干扰特殊规则

> 引用：灾难系统设计.md §2.6 M4 预言干扰

- M4关卡中蓝图材料变化时，已放置的方块保持不变
- 新增方块需按新蓝图材料执行
- 合成表仍按当前庇护环境索引，但蓝图要求的材料可能变化
- 玩家需预留多余材料灵活应变

### 4.5 M1元素枯竭特殊规则

> 引用：灾难系统设计.md §2.6 M1 元素枯竭

- 合成所需碎片数量翻倍
- 例如：水砖原本冰晶×2 → 变为冰晶×4
- 合成时间不变

## 五、网络同步

### 5.1 同步内容

合成系统为本地操作，同步通过材料产出事件间接实现：

| 事件 | 发起方 | 同步内容 |
|------|--------|----------|
| 材料产出 | 操作玩家 | 材料类型、数量、玩家ID |
| 合成台占用 | 操作玩家 | 合成台ID、玩家ID |
| 合成打断 | 操作玩家 | 合成台ID（释放占用） |

> 合成台占用状态属于中频状态同步，10Hz 更新。引用：网络通信.md §3.3
