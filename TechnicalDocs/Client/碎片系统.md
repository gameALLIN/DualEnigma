## 一、系统概述

### 1.1 系统职责

碎片系统负责：
- 3 种碎片的掉落计划生成与物理模拟
- 碎片存续时间管理（3秒后消失）
- 碎片收集检测与接住方式判定（×1 / ×2 / ×3）
- 温砖触发逻辑（火人点燃+水人冻结同一碎片）
- 碎片对象池管理

### 1.2 在整体架构中的位置

```
Core（ObjectPool / EventBus / ServiceLocator）
         │
    FragmentSystem
    │         │
    ├── 碎片掉落计划生成（Host 权威）
    ├── 碎片物理模拟（双方各自模拟，种子同步）
    ├── 碎片存续倒计时
    ├── 收集检测（Trigger2D → 接住方式判定）
    ├── 温砖触发判定
    └── 碎片对象池（FragmentPool）
              │
     依赖：CharacterSystem / SkillSystem / SynthesisSystem
```

### 1.3 依赖关系

| 依赖方向 | 说明 |
|----------|------|
| Fragment → Core | ObjectPool / EventBus / ServiceLocator |
| Fragment → Character | 收集检测时通知角色 |
| Fragment → Skill | 被动技能触发（寒霜体质/烈焰体质） |
| Fragment → Synthesis | 碎片合成时消耗 |
| Network → Fragment | 掉落计划同步 / 接住冲突判定 |

## 二、数据结构

### 2.1 碎片类型枚举

```csharp
namespace DualEnigma.Fragment
{
    /// <summary>
    /// 碎片类型。只有3种基础碎片。
    /// 引用：GDD v6.1 §4.1
    /// </summary>
    public enum FragmentType
    {
        /// <summary>冰晶碎片（★ 数量最多，蓝白棱形）</summary>
        IceCrystal,
        /// <summary>熔岩碎片（★★ 橙红不规则形）</summary>
        Lava,
        /// <summary>岩石碎片（★★★ 数量最少，灰色方形）</summary>
        Rock,
    }

    /// <summary>
    /// 碎片状态枚举
    /// </summary>
    public enum FragmentState
    {
        /// <summary>掉落中（空中或刚落地，可被接住）</summary>
        Falling,
        /// <summary>已被接住</summary>
        Collected,
        /// <summary>自然消失</summary>
        Despawned,
        /// <summary>被点燃（火人被动触发）</summary>
        Ignited,
        /// <summary>被冻结（水人被动触发）</summary>
        Frozen,
        /// <summary>转化为温砖</summary>
        ConvertedToWarmBrick,
    }
}
```

### 2.2 掉落计划数据

```csharp
namespace DualEnigma.Fragment
{
    /// <summary>
    /// 单个碎片的掉落计划项。由 Host 生成，同步给 Client。
    /// 引用：网络通信.md §4.1 碎片掉落计划同步
    /// </summary>
    [System.Serializable]
    public struct FragmentDropPlan
    {
        /// <summary>碎片唯一ID</summary>
        public int FragmentId;
        /// <summary>碎片类型</summary>
        public FragmentType Type;
        /// <summary>掉落位置（世界坐标）</summary>
        public Vector2 Position;
        /// <summary>掉落时间（相对阶段开始的秒数）</summary>
        public float DropTime;
        /// <summary>随机种子（用于物理模拟一致性）</summary>
        public uint Seed;
    }
}
```

### 2.3 碎片密度参数

| 阶段 | 碎片数量 | 说明 |
|------|----------|------|
| 预告（5秒） | 3-5个 | 预热，少量碎片掉落 |
| 碎片收集（15秒） | 20-30个 | 主要收集阶段 |
| 灾害预告及之后 | 0 | 停止掉落 |
| **每轮总计** | **23-35个** | 与密度系数叠加 |

**密度系数**（引用：章节策划文档_v2.0.md §3.1）：

| 轮次 | 密度系数 | 实际碎片总数 |
|------|----------|-------------|
| 1 | ×1.0 | 23-35个 |
| 2 | ×0.85 | 20-30个 |
| 3 | ×0.7 | 16-25个 |

### 2.4 存续时间

| 轮次 | 存续时间 | 说明 |
|------|----------|------|
| 1 | 3.5秒 | 碎片落地后未捡起则消失 |
| 2 | 3.0秒 | |
| 3 | 2.5秒 | |

## 三、核心接口与类设计

### 3.1 FragmentSystem

```csharp
namespace DualEnigma.Fragment
{
    /// <summary>
    /// 碎片系统管理器。继承 Singleton<T>，注册 IFragmentSystem 到 ServiceLocator。
    /// </summary>
    public class FragmentSystem : Singleton<FragmentSystem>, IFragmentSystem
    {
        /// <summary>当前场上存活的碎片数量</summary>
        public int ActiveCount { get; }

        /// <summary>生成碎片掉落计划（Host 调用）</summary>
        /// <param name="disasterType">当前灾难类型</param>
        /// <param name="densityFactor">密度系数</param>
        /// <param name="seed">随机种子</param>
        public List<FragmentDropPlan> GenerateDropPlan(int disasterType, float densityFactor, uint seed);

        /// <summary>执行掉落计划（双方各自调用）</summary>
        public void ExecuteDropPlan(List<FragmentDropPlan> plan);

        /// <summary>碎片被接住（由角色碰撞触发）</summary>
        /// <param name="fragmentId">碎片ID</param>
        /// <param name="playerId">接住的角色（0=Aqua, 1=Ignis）</param>
        /// <param name="isJumping">是否跳跃中接住</param>
        public void OnFragmentCollected(int fragmentId, byte playerId, bool isJumping);

        /// <summary>碎片自然消失</summary>
        public void OnFragmentDespawned(int fragmentId);
    }

    public interface IFragmentSystem
    {
        int ActiveCount { get; }
        void OnFragmentCollected(int fragmentId, byte playerId, bool isJumping);

        /// <summary>查询碎片类型（包括已收集但未消耗的碎片）</summary>
        /// <param name="fragmentId">碎片唯一ID</param>
        /// <param name="type">输出的碎片类型</param>
        /// <returns>是否查找到对应碎片</returns>
        bool TryGetFragmentType(int fragmentId, out FragmentType type);

        /// <summary>获取当前场上所有活跃碎片的列表</summary>
        /// <returns>活跃碎片列表的副本</returns>
        List<FragmentController> GetActiveFragments();
    }
}
```

### 3.2 FragmentController

```csharp
namespace DualEnigma.Fragment
{
    /// <summary>
    /// 碎片控制器，挂载在碎片 GameObject 上。
    /// 使用 Trigger2D 检测角色碰撞，管理存续倒计时。
    /// </summary>
    [RequireComponent(typeof(Collider2D))]
    public class FragmentController : MonoBehaviour
    {
        /// <summary>碎片唯一ID</summary>
        public int FragmentId { get; set; }
        /// <summary>碎片类型</summary>
        public FragmentType Type { get; set; }
        /// <summary>当前状态</summary>
        public FragmentState State { get; private set; }
        /// <summary>存续剩余时间（秒）</summary>
        public float RemainingTime { get; private set; }

        /// <summary>初始化碎片</summary>
        public void Initialize(FragmentDropPlan plan, float lifetime);

        /// <summary>设置状态</summary>
        public void SetState(FragmentState state);

        /// <summary>重置碎片状态，供对象池回收后复用前调用</summary>
        public void ResetState();

        /// <summary>点燃碎片（由被动技能 FlameAura 触发）</summary>
        public void SetIgnited();

        /// <summary>冻结碎片（由被动技能 FrostAura 触发）</summary>
        public void SetFrozen();
    }
}
```

## 四、详细逻辑

### 4.1 掉落逻辑

**掉落区域**：建筑区域外（危险区），距离建筑区域边界 10 格内。

**掉落计划生成流程**：

```
Host 端（预告阶段/碎片收集阶段开始时）:
  1. 根据灾难类型和密度系数确定碎片总数
  2. 随机分配碎片类型（冰晶占比最高，岩石最少）
  3. 在建筑区域外 10 格内随机生成掉落位置
  4. 为每个碎片分配掉落时间和随机种子
  5. 将掉落计划打包为 Protobuf 消息，可靠通道发送给 Client
  6. 双方各自按计划执行物理掉落模拟

Client 端:
  1. 接收掉落计划
  2. 本地模拟碎片物理掉落（与 Host 使用相同随机种子，确保轨迹一致）
  3. 碎片接住事件发送给 Host
```

**阶段过渡规则**：
- 预告阶段：3-5个碎片预热掉落
- 碎片收集阶段：20-30个碎片主批量掉落
- 灾害预告阶段开始：停止新增掉落
- 已掉落的碎片继续存在，按存续时间自然消失

### 4.2 存续管理

```
碎片落地
    → 启动存续倒计时（3.5s / 3.0s / 2.5s，按轮次）
    → 倒计时归零
        → 碎片自然消失（不产生碎片）
        → EventBus.Publish(new FragmentDespawnedEvent { fragmentId })
        → 归还到 FragmentPool
```

### 4.3 收集检测

**碰撞检测**：使用 `Collider2D` + `isTrigger = true`，角色进入触发器范围时判定接住。

**接住方式判定**：

| 方式 | 倍率 | 判定条件 |
|------|------|----------|
| 地面接住 | ×1 | 角色在地面（IsGrounded=true） |
| 跳跃接住 | ×2 | 角色不在地面（IsGrounded=false） |
| 同时接住 | ×3 | 两人接住事件时间差 < 100ms |

**同时接住冲突处理**：

```
场景：两人同时接住同一碎片（触发×3奖励）
条件：两人接住事件的时间差 < 100ms
判定：Host 判定为同时接住，触发×3碎片奖励
回滚：Client 回滚本地状态，采纳 Host 判定结果

引用：网络通信.md §4.1 碎片接住冲突处理
```

**被动技能触发**：

| 角色 | 被动 | 基础概率 | 跳跃概率 | 同时接住概率 |
|------|------|----------|----------|-------------|
| 水人 | 寒霜体质（冻结） | 30% | 50% | 100% |
| 火人 | 烈焰体质（点燃） | 30% | 50% | 100% |

### 4.4 温砖触发

**触发条件**：火人点燃碎片 + 水人冻结同一碎片 = 温砖

**完整操作链**：

```
1. 碎片处于"掉落中"状态（未被捡起）
2. 火人走到落点/跳跃接住 → 触发被动"烈焰体质"点燃碎片
3. 水人同时走到落点/跳跃接住 → 触发被动"寒霜体质"冻结同一碎片
4. 两者作用于同一碎片 → 碎片转化为温砖
5. 温砖不再可拆分，可作为任意蓝图的增强材料
```

**温砖属性**：

| 属性 | 值 | 说明 |
|------|-----|------|
| HP | 20 | 比普通砖高 |
| 抗性 | 全抗性+20% | 所有环境均有效 |
| 特殊 | 3×3区域内灾害效果减弱 | 放置后产生温差场 |
| 限制 | 不可用于普通合成，仅用于建造 | |

**待决策项**：

> 🔴 **-F4 温砖触发窗口**：触发窗口未最终确定。候选方案：①2格内 ②容错5秒 ③不改。待原型验证后敲定。

### 4.5 对象池集成

**FragmentPool**：使用 `ObjectPool<FragmentController>` 复用碎片 GameObject。

| 参数 | 值 | 说明 |
|------|-----|------|
| 预制体 | FragmentPrefab | 程序化生成的碎片预制体 |
| 预加载数量 | 40 | 覆盖峰值（每轮最多35个） |
| 父节点 | FragmentPoolRoot | 场景中的空 GameObject |

**生命周期**：

```
关卡开始 → Prewarm(40) → 预实例化 40 个 inactive 碎片
    ↓
掉落 → Get() → 设为 active，Initialize(plan)
    ↓
消失/被接住 → Release(fragment) → 设为 inactive，归还到池中
    ↓
关卡结束 → Clear() → 销毁所有碎片
```

## 五、网络同步

### 5.1 同步内容

> 引用：网络通信.md §4.1 碎片系统同步

| 事件 | 发起方 | 同步内容 | 处理方式 |
|------|--------|----------|----------|
| 碎片掉落 | **Host** | 碎片掉落计划（位置/类型/时间/种子） | 一次性同步，双方各自模拟 |
| 碎片接住 | 实际接住的玩家 | 碎片ID、玩家ID、接住时间戳 | 同步给对方，Host 判定冲突 |
| 碎片消失 | 各端独立 | 无需同步 | 各端独立模拟倒计时 |

> 引用：网络通信.md §3.3 中频状态同步

| 字段 | 类型 | 频率 |
|------|------|------|
| fragments[] | FragmentSync[] | 10Hz（100ms） |
