## 一、系统概述

### 1.1 系统职责

数据管理负责：
- 静态配置数据管理（关卡/灾难/合成/建筑/技能/天赋配置）
- 运行时数据管理（玩家状态/建筑状态/碎片状态/游戏进度）
- 导表工具集成（Excel → JSON → 运行时加载）
- ScriptableObject 配置体系
- 存档系统（章节存档点，待设计）

### 1.2 在整体架构中的位置

```
Core（ResMgr / AssetBundleMgr）
         │
    DataManager
    │           │
    ├── 静态配置加载（JSON / ScriptableObject）
    ├── 运行时数据缓存
    ├── 导表工具集成（GameDesign/tool/）
    └── 存档系统（待设计）
              │
     为所有系统提供配置数据
```

### 1.3 依赖关系

| 依赖方向 | 说明 |
|----------|------|
| Data → Core | ResMgr 加载资源 |
| 各系统 → Data | 读取配置数据 |
| 导表工具 → Data | 产出 JSON 配置文件 |

## 二、数据结构

### 2.1 数据分类

| 数据类型 | 说明 | 存储形式 | 加载时机 |
|----------|------|----------|----------|
| **静态配置** | 关卡/灾难/合成/建筑/技能/天赋配置 | JSON + ScriptableObject | 游戏启动 |
| **运行时数据** | 玩家状态/建筑状态/碎片状态/游戏进度 | 内存对象 | 运行时创建 |

### 2.4 运行时数据结构

```csharp
namespace DualEnigma.Data
{
    /// <summary>
    /// 运行时数据容器，由 GameManager 持有。
    /// </summary>
    [System.Serializable]
    public class RuntimeData
    {
        /// <summary>游戏进度</summary>
        public GameProgress Progress;
        /// <summary>当前阶段</summary>
        public GamePhase CurrentPhase;
        /// <summary>水人运行时状态</summary>
        public PlayerRuntimeData AquaData;
        /// <summary>火人运行时状态</summary>
        public PlayerRuntimeData IgnisData;
        /// <summary>当前蓝图</summary>
        public List<BlueprintBlock> CurrentBlueprint;
        /// <summary>所有建筑</summary>
        public List<BuildingData> Buildings;
        /// <summary>当前灾难ID</summary>
        public int CurrentDisasterId;
    }

    [System.Serializable]
    public class PlayerRuntimeData
    {
        public int HP;
        public float ShelterEnergy;
        public List<int> CarriedFragments;
        public List<int> SelectedTalents;
        public int SelectedESkillId;
        public int SelectedQSkillId;
        public float ESCooldown;
        public float QSCooldown;
    }
}
```

## 三、核心接口与类设计

### 3.1 DataManager

```csharp
namespace DualEnigma.Data
{
    /// <summary>
    /// 数据管理器。继承 Singleton<T>。
    /// 负责加载、缓存和提供所有配置数据。
    /// </summary>
    public class DataManager : Singleton<DataManager>
    {
        /// <summary>已加载的 JSON 配置缓存</summary>
        private Dictionary<string, object> _jsonCache;

        /// <summary>已加载的 ScriptableObject 配置缓存</summary>
        private Dictionary<System.Type, ScriptableObject> _soCache;

        /// <summary>初始化数据管理器（由 GameLaunch 调用）</summary>
        public void Initialize();

        /// <summary>加载 JSON 配置</summary>
        /// <typeparam name="T">反序列化目标类型</typeparam>
        /// <param name="configName">配置名（如 "disaster"）</param>
        public T LoadJson<T>(string configName) where T : class;

        /// <summary>加载 ScriptableObject 配置</summary>
        /// <typeparam name="T">配置类型</typeparam>
        public T LoadConfig<T>() where T : ScriptableObject;
    }
}
```

## 四、详细逻辑

### 4.1 导表工具集成

**工具位置**: `GameDesign/tool/`

**工作流程**：

```
策划维护 Excel 表（GameDesign/Excel/*.xlsx）
    ↓
导表工具（python src/main.py export）
    ↓
产出 JSON 文件（tool/output/client/*.json）
    ↓
复制到 Unity 工程（AssetPackage/Data/）
    ↓
运行时由 DataManager 加载
```

**导表工具特性**：
- C/S/CS 标记控制导出范围
- 类型系统支持 int/float/string/bool/enum/list
- 注释功能（# 前缀跳过 Sheet/列/行）
- 自动校验（主键唯一/必填/类型/枚举）
- 产出客户端 JSON + 服务器 TSV

> 引用：`GameDesign/tool/README.md` 导表工具完整文档

### 4.2 数据加载流程

```
GameLaunch.Awake()
    │
    ├── ResMgr.Instance.Init()              ← 已实现
    │   ├── Editor: AssetDatabase 直接加载
    │   └── Runtime: AssetBundleMgr 加载
    │
    ├── DataManager.Instance.Initialize()   ← 待实现
    │   ├── 加载 ScriptableObject 配置（从 data AB）
    │   │   ├── CharacterConfig
    │   │   ├── DisasterConfig
    │   │   ├── SkillConfig
    │   │   ├── TalentConfig
    │   │   ├── SynthesisConfig
    │   │   ├── BuildingConfig
    │   │   ├── ResistanceMatrix
    │   │   ├── ShelterConfig
    │   │   └── RoundConfig
    │   │
    │   └── 加载 JSON 配置（从 data AB）
    │       ├── disaster.json
    │       ├── skill.json
    │       ├── talent.json
    │       ├── synthesis.json
    │       ├── resistance.json
    │       └── level.json
    │
    └── 各系统从 DataManager 获取配置
```

## 六、配置数据

### 6.1 ScriptableObject 与 JSON 的分工

| 数据类型 | 使用 ScriptableObject | 使用 JSON 导表 |
|----------|----------------------|----------------|
| 常量参数 | ✅ 适合（阶段时长等） | |
| 大量条目 | | ✅ 适合（35种灾难、53个天赋） |
| 策划频繁修改 | | ✅ 适合（Excel 编辑 → 导出） |
| 需要类型安全 | ✅ 适合 | |
| 需要版本控制友好 | | ✅ 适合（JSON diff） |

### 6.2 配置加载路径

| 配置类型 | AB Bundle | 路径 |
|----------|-----------|------|
| ScriptableObject | `data` | `Data/{ConfigName}.asset` |
| JSON | `data` | `Data/{ConfigName}.json` |
