## 一、系统概述

### 1.1 系统职责

建造系统负责：
- 15×8 格建筑区域网格管理
- 蓝图生成与显示（灾害预告阶段）
- 建筑放置/修补/拆除操作
- 建筑抗性计算与 HP 管理
- M4预言干扰特殊蓝图处理

### 1.2 在整体架构中的位置

```
Core（EventBus / ServiceLocator / ObjectPool）
         │
    BuildingSystem
    │            │
    ├── 网格系统（15×8 坐标系）
    ├── 蓝图管理（动态生成 → 显示 → 完成/拆除判定）
    ├── 建筑操作（放置/修补/拆除）
    ├── 抗性计算（建筑×材料×环境）
    └── 建筑HP管理（承受灾害 → 修整校正）
              │
     依赖：SynthesisSystem / DisasterSystem / ShelterSystem
```

### 1.3 依赖关系

| 依赖方向 | 说明 |
|----------|------|
| Building → Core | EventBus / ServiceLocator / ObjectPool |
| Building → Synthesis | 消耗合成产出的材料 |
| Building → Disaster | 建筑承受灾害伤害 |
| Building → Shelter | 建筑区域内安全规则 |
| Network → Building | 建筑放置/摧毁事件同步 |

## 三、核心接口与类设计

### 3.1 BuildingSystem

```csharp
namespace DualEnigma.Building
{
    /// <summary>
    /// 建造系统管理器。继承 Singleton<T>，注册 IBuildSystem 到 ServiceLocator。
    /// </summary>
    public class BuildingSystem : Singleton<BuildingSystem>, IBuildSystem
    {
        /// <summary>当前蓝图块列表</summary>
        public List<BlueprintBlock> CurrentBlueprint { get; }

        /// <summary>所有已放置建筑</summary>
        public List<BuildingData> Buildings { get; }

        /// <summary>生成蓝图（灾害预告阶段调用）</summary>
        /// <param name="disasterType">灾难类型</param>
        /// <param name="round">当前轮次（决定块数）</param>
        public void GenerateBlueprint(int disasterType, int round);

        /// <summary>放置建筑</summary>
        /// <param name="playerId">操作玩家</param>
        /// <param name="type">建筑类型</param>
        /// <param name="material">材料类型</param>
        /// <param name="gridPos">网格坐标</param>
        /// <param name="facing">朝向</param>
        /// <returns>是否放置成功</returns>
        public bool PlaceBuilding(byte playerId, BuildingType type, MaterialType material, Vector2Int gridPos, int facing);

        /// <summary>修补建筑（修整阶段）</summary>
        public bool RepairBuilding(byte playerId, int buildingId);

        /// <summary>拆除建筑</summary>
        public bool DemolishBuilding(byte playerId, int buildingId);

        /// <summary>建筑受伤害（灾害冲击阶段）</summary>
        public void DamageBuilding(int buildingId, float damage);

        /// <summary>修整阶段校正所有建筑HP（Host调用）</summary>
        public void SyncBuildingHPs();
    }

    public interface IBuildSystem
    {
        List<BuildingData> Buildings { get; }
        bool PlaceBuilding(byte playerId, BuildingType type, MaterialType material, Vector2Int gridPos, int facing);
        void DamageBuilding(int buildingId, float damage);
    }
}
```

## 四、详细逻辑

### 4.1 建筑区域

| 参数 | 值 | 说明 |
|------|-----|------|
| 区域大小 | 15×8格（480×256像素） | PPU=32 |
| 安全区 | 建筑区域内 | 灾害冲击阶段50%伤害减免 |
| 建造条件 | 两人必须同时在区域内 | |
| 碎片限制 | 建筑区域内不能捡碎片 | |

### 4.2 蓝图系统

**蓝图生成规则**：

| 规则 | 说明 |
|------|------|
| 蓝图位置 | 关卡系统根据灾害类型动态生成 |
| 蓝图形状 | 根据建筑类型定义（防火墙=竖线，防洪堤=横线，加固塔=金字塔，避难所=矩形，导流板=斜线） |
| 蓝图块数 | 轮次1: 3-4块 / 轮次2: 5-6块 / 轮次3: 7-8块 / 最终关: 9-10块 |
| 蓝图位置约束 | 必须在15×8格建筑区域内，根据灾难入侵方向布置 |
| 蓝图组合 | 单关蓝图可包含多种建筑类型 |
| 蓝图显示 | 灾害预告阶段(③)显示完整蓝图位置和材料需求 |

**M4预言干扰**：
- 蓝图材料需求在建造中随机变化（每轮2-3次）
- 已放置的方块不受影响
- 预警提示：蓝图闪烁3秒后改变
- 仅改变材料需求，蓝图位置和形状不变

### 4.3 网格系统

- 15×8 网格坐标系，原点(0,0)为左下角
- 建筑放置检测：同一格只能存在1个建筑
- 建筑必须放置在地面上或已有建筑之上

### 4.4 建筑操作

| 操作 | 耗时 | 阶段限制 | 说明 |
|------|------|----------|------|
| 放置 | 0.5秒/块 | 建造阶段 | 消耗1个材料，朝向正确正常抗性，放反抗性降一级 |
| 修补 | 1秒/块 | 仅修整阶段 | 消耗1个同类材料，恢复50%基础HP |
| 拆除 | 1秒/块 | 建造阶段+修整阶段 | 已放置方块可拆除，材料不返还 |

**放置流程**：

```
玩家选择建筑类型 + 材料 + 朝向
    → 检查两人是否同时在建筑区域内
        ├── 否 → 提示"需两人同时在建筑区域内"
        └── 是 → 检查网格是否可用
            ├── 已占用 → 提示"位置已被占用"
            └── 可用 → 检查材料是否足够
                ├── 不足 → 提示"材料不足"
                └── 足够 → 消耗材料，0.5秒放置计时
                    → 计时完成 → 创建建筑实例
                    → EventBus.Publish(new BuildingPlacedEvent { ... })
```

### 4.5 建筑抗性矩阵

> 引用：灾难系统设计.md §4.3 建筑×材料×环境 抗性矩阵

**抗性等级定义**：

| 等级 | 符号 | 伤害系数 |
|------|------|----------|
| 免疫 | ★★★ | 0× |
| 强抗性 | ★★ | 0.3× |
| 抗性 | ★ | 0.6× |
| 无加成 | — | 1.0× |
| 弱点 | ✗ | 1.5× |

**朝向规则**：
- 朝向正确：正常抗性等级
- 放反（朝向错误）：抗性降一级（如 ★★★ → ★★）

**特殊机制**：
- 暴风雪环境：冰砖 HP+50%（如防火墙 50→75HP）
- 温砖：全抗性+20%，HP20，3×3温差场

**最佳搭配示例**：

| 环境 | 最佳搭配 | 效果 |
|------|----------|------|
| 火山 | 防火墙+冰砖 | 免疫火焰伤害 |
| 洪水 | 防洪堤+岩浆砖 | 免疫洪水伤害 |
| 暴风雪 | 避难所+冰砖 | 冰砖强化+50%HP |
| 地震 | 加固塔+石砖 | 免疫地震伤害 |
| 陨石 | 避难所+石砖 | 坚固掩体 |

### 4.6 建筑HP管理

```
灾害冲击阶段:
    → DisasterSystem 计算伤害 = DPS × 抗性系数 × 当前强度
    → BuildingSystem.DamageBuilding(buildingId, damage)
    → 建筑HP -= damage
    → HP ≤ 0 → 建筑摧毁
        → EventBus.Publish(new BuildingDestroyedEvent { ... })
        → Host 判定并同步给 Client

修整阶段:
    → Host 同步所有建筑当前HP（校正双方偏差）
    → 玩家可修补受损建筑
```

## 五、网络同步

### 5.1 同步内容

> 引用：网络通信.md §4.3 建筑系统同步

| 事件 | 发起方 | 同步内容 | 处理方式 |
|------|--------|----------|----------|
| 建筑放置 | 操作玩家 | 建筑类型、材料类型、网格位置 | 同步给对方，双方各自创建实例 |
| 建筑受损 | 各端独立 | 无需实时同步 | 双方各自计算（确定性时间轴） |
| 建筑修整同步 | **Host** | 所有建筑当前HP | 修整阶段开始时Host校正偏差 |
| 建筑摧毁 | **Host** | 建筑ID、摧毁原因 | Host判定HP≤0时触发，同步给Client |

### 5.2 建筑抗性等级参考

双方各自独立计算建筑受伤（基于灾难DPS × 抗性系数 × 当前强度），修整阶段由Host校正累积偏差。
