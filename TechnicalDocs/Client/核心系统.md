## 一、系统概述

### 1.1 系统职责

核心系统是所有游戏模块的基础设施层，提供：

| 基础设施 | 职责 | 状态 |
|----------|------|------|
| `Singleton<T>` | 泛型单例基类，全局唯一实例管理 | ✅ 已实现 |
| `GameLaunch` | 游戏启动入口，系统初始化编排 | ✅ 已实现 |
| `ResMgr` / `AssetBundleMgr` | 资源加载与 AssetBundle 管理 | ✅ 已实现 |
| `EventBus` | 事件总线，模块间松耦合通信 | 🔲 待实现 |
| `ServiceLocator` | 服务定位器，接口注册与获取 | 🔲 待实现 |
| `GameStateMachine` | 游戏状态机，7阶段流转管理 | 🔲 待实现 |
| `ObjectPool<T>` | 通用对象池，GameObject 复用 | 🔲 待实现 |
| `GameManager` | 游戏全局状态与单局生命周期管理 | 🔲 待实现 |

### 1.2 在整体架构中的位置

```
┌─────────────────────────────────────────────────────┐
│                     Core 层                          │
│  Singleton<T>  GameLaunch  ResMgr  AssetBundleMgr   │
│  EventBus  ServiceLocator  GameStateMachine          │
│  ObjectPool<T>  GameManager                          │
├──────────────┬──────────────┬───────────────────────┤
│  Character   │  Fragment    │  Synthesis            │
│  Building   │  Disaster     │  Shelter              │
│  Skill      │  Talent       │  Data / Network / UI  │
└──────────────┴──────────────┴───────────────────────┘
```

所有业务模块依赖 Core 层提供的单例基类、事件总线和服务定位器。

### 1.3 依赖关系

| 依赖方向 | 说明 |
|----------|------|
| Core → 无 | Core 层不依赖任何业务模块 |
| 业务模块 → Core | 所有业务模块继承 `Singleton<T>`，使用 `EventBus` 和 `ServiceLocator` |
| Core → Unity | 依赖 `UnityEngine`（MonoBehaviour、Rigidbody2D 等） |

## 二、数据结构

### 2.1 游戏阶段枚举

```csharp
namespace DualEnigma.Core
{
    /// <summary>
    /// 游戏阶段枚举，对应单轮 90 秒的 7 个阶段。
    /// 引用：章节策划文档_v2.0.md §4.1
    /// </summary>
    public enum GamePhase
    {
        /// <summary>① 预告（5秒）：显示灾难类型、庇护环境、建筑蓝图</summary>
        Preview,
        /// <summary>② 碎片收集（15秒）：碎片在建筑区域外掉落</summary>
        FragmentCollect,
        /// <summary>③ 灾害预告（5秒）：灾害方向指示，玩家应返回建筑区域</summary>
        DisasterPreview,
        /// <summary>④ 建造（20秒）：合成材料并按蓝图建造</summary>
        Build,
        /// <summary>⑤ 灾害冲击（20秒）：灾害渐进入侵</summary>
        DisasterImpact,
        /// <summary>⑥ 修整（10秒）：评估损伤、快速修补</summary>
        Rest,
        /// <summary>⑦ 升级（15秒）：天赋选择（3选1）</summary>
        Upgrade,
    }
}
```

### 2.2 游戏进度数据

```csharp
namespace DualEnigma.Core
{
    /// <summary>
    /// 当前关卡进度。3章 × 4节 × 3轮 = 36关。
    /// 编号规则：章-节-轮（如 2-3-1 = 第二章第三节第一轮）
    /// </summary>
    [System.Serializable]
    public class GameProgress
    {
        /// <summary>当前章节 (1-3)</summary>
        public int Chapter = 1;
        /// <summary>当前节 (1-4)</summary>
        public int Section = 1;
        /// <summary>当前轮 (1-3)</summary>
        public int Round = 1;

        /// <summary>全局轮次编号 (1-36)</summary>
        public int GlobalRound => (Chapter - 1) * 12 + (Section - 1) * 3 + Round;

        /// <summary>章节难度倍率</summary>
        public float ChapterMultiplier => Chapter switch
        {
            1 => 0.8f,
            2 => 1.0f,
            3 => 1.2f,
            _ => 1.0f,
        };

        /// <summary>轮次难度倍率</summary>
        public float RoundMultiplier => Round switch
        {
            1 => 1.0f,
            2 => 1.3f,
            3 => 1.6f,
            _ => 1.0f,
        };

        /// <summary>综合难度倍率 = 章节倍率 × 轮次倍率</summary>
        public float DifficultyMultiplier => ChapterMultiplier * RoundMultiplier;
    }
}
```

```csharp
namespace DualEnigma.Core
```

## 三、核心接口与类设计

### 3.1 Singleton\<T>（已实现）

**代码位置**: `Scripts/Core/Singleton.cs`
**命名空间**: `DualEnigma.Core`

| 成员 | 签名 | 说明 |
|------|------|------|
| `Instance` | `static T Instance { get; }` | 全局唯一实例，不存在时自动创建 |
| `HasInstance` | `static bool HasInstance` | 实例是否已存在 |
| `OnSingletonInitialized()` | `protected virtual void` | 子类重写，执行初始化逻辑 |

**使用约定**：
- 所有 Manager 类继承 `Singleton<T>`，如 `public class EventBus : Singleton<EventBus>`
- 自动 `DontDestroyOnLoad`，场景切换不销毁
- 场景中多实例时只保留第一个，其余自动销毁

### 3.2 EventBus（待实现）

**命名空间**: `DualEnigma.Core`

```csharp
namespace DualEnigma.Core
{
    /// <summary>
    /// 事件总线，模块间松耦合通信。
    /// MonoBehaviour 单例，继承 Singleton<T>。
    /// </summary>
    public class EventBus : Singleton<EventBus>
    {
        /// <summary>订阅指定类型的事件</summary>
        public void Subscribe<T>(Action<T> handler) where T : struct, IEventData;

        /// <summary>取消订阅</summary>
        public void Unsubscribe<T>(Action<T> handler) where T : struct, IEventData;

        /// <summary>发布事件，触发所有订阅者</summary>
        public void Publish<T>(T eventData) where T : struct, IEventData;
    }

    /// <summary>事件数据标记接口，所有事件结构体实现此接口</summary>
    public interface IEventData { }
}
```

**事件命名规范**: `{系统名}{动作}Event`，采用结构体（struct）避免 GC。

**全局事件清单**：

| 事件类型 | 发布方 | 订阅方 | 说明 |
|----------|--------|--------|------|
| `PhaseChangedEvent` | GameStateMachine | 各系统 | 阶段切换通知 |
| `FragmentCollectedEvent` | FragmentSystem | UI / Skill / Shelter | 碎片被收集 |
| `FragmentDespawnedEvent` | FragmentSystem | UI | 碎片自然消失 |
| `BuildingPlacedEvent` | BuildingSystem | UI / Disaster | 建筑放置完成 |
| `BuildingDestroyedEvent` | DisasterSystem | BuildingSystem / UI | 建筑被摧毁 |
| `DisasterStartedEvent` | DisasterSystem | UI / Shelter | 灾害冲击阶段开始 |
| `DisasterEndedEvent` | DisasterSystem | UI / Shelter | 灾害冲击阶段结束 |
| `SkillActivatedEvent` | SkillSystem | UI / Disaster | 技能释放 |
| `TalentSelectedEvent` | TalentSystem | Character / Skill / Shelter | 天赋选择完成 |
| `PlayerDamagedEvent` | ShelterSystem | UI | 角色受伤 |
| `PlayerDiedEvent` | ShelterSystem | GameManager | 角色死亡，触发游戏结束 |
| `GameStartEvent` | GameManager | 各系统 | 单局开始 |
| `GameEndEvent` | GameManager | 各系统 / UI | 单局结束 |
| `GamePauseEvent` | GameManager | 各系统 | 游戏暂停 |
| `GameResumeEvent` | GameManager | 各系统 | 游戏恢复 |

### 3.3 ServiceLocator（待实现）

**命名空间**: `DualEnigma.Core`

```csharp
namespace DualEnigma.Core
{
    /// <summary>
    /// 服务定位器，提供接口注册与获取。
    /// 各系统 Manager 在初始化时注册自身接口，其他系统通过接口获取服务。
    /// </summary>
    public static class ServiceLocator
    {
        /// <summary>注册服务接口</summary>
        public static void Register<T>(T service) where T : class;

        /// <summary>获取服务接口，未注册时返回 null</summary>
        public static T Get<T>() where T : class;

        /// <summary>注销服务接口</summary>

}
```

## 四、详细逻辑

### 4.1 游戏状态机流转

```
单轮流程（90秒）：

Preview(5s) → FragmentCollect(15s) → DisasterPreview(5s) → Build(20s) → DisasterImpact(20s) → Rest(10s) → Upgrade(15s)
                                                                                                                      │
                                                              ←─────────────────────────────────────────────────────┘
                                                              ↓
                                                         下一轮 Preview
```

**各阶段时间定义**：

| 阶段 | 枚举值 | 时长（秒） | 触发事件 |
|------|--------|-----------|----------|
| ① 预告 | `Preview` | 5 | `PhaseChangedEvent { phase = Preview }` |
| ② 碎片收集 | `FragmentCollect` | 15 | `PhaseChangedEvent { phase = FragmentCollect }` |
| ③ 灾害预告 | `DisasterPreview` | 5 | `PhaseChangedEvent { phase = DisasterPreview }` |
| ④ 建造 | `Build` | 20 | `PhaseChangedEvent { phase = Build }` |
| ⑤ 灾害冲击 | `DisasterImpact` | 20 | `PhaseChangedEvent { phase = DisasterImpact, disasterId }` |
| ⑥ 修整 | `Rest` | 10 | `PhaseChangedEvent { phase = Rest }` |
| ⑦ 升级 | `Upgrade` | 15 | `PhaseChangedEvent { phase = Upgrade }` |

**关卡进度推进规则**：
- 每轮 Upgrade 结束 → `AdvanceToNextLevel()`
- 轮次 1→2→3 循环，轮次 3 结束后进入下一节
- 节 1→2→3→4 循环，节 4 结束后进入下一章
- 章 1→2→3，章 3 轮次 3 结束 → `EndGame(true)`（胜利）
- 任意角色 HP 归零 → `EndGame(false)`（失败）

### 4.2 EventBus 事件流转示例

以 **HUD 显示 HP** 为例：

```
游戏逻辑层（角色受伤）
    → EventBus.Instance.Publish(new PlayerDamagedEvent { playerId, damage })
        → HUDController.OnPlayerDamaged()
            → HUDModel.SetHP(currentHP)
                → HUDView.RefreshHP(hp)  → 屏幕更新
```

以 **阶段切换** 为例：

```
GameStateMachine 计时器到点
    → EventBus.Instance.Publish(new PhaseChangedEvent { phase = DisasterImpact })
        → DisasterSystem.OnPhaseChanged() → 启动灾难
        → ShelterSystem.OnPhaseChanged() → 启用庇护环境伤害
        → UIManager.OnPhaseChanged() → 更新 HUD 阶段显示
        → FragmentSystem.OnPhaseChanged() → 停止碎片掉落
```

### 4.4 ObjectPool 生命周期

```
预加载（关卡开始时）
    │
    ├── Prewarm(initialSize) → 实例化 N 个 GameObject，设为 inactive
    │
    ├── Get() → 从池中取出一个 inactive 对象，设为 active，返回
    │
    └── Release(item) → 设为 inactive，归还到池中

清空（关卡结束时）
    └── Clear() → 销毁所有池中对象
```
