## 一、FragmentPlanner — 碎片掉落计划生成

服务器在 Preview 阶段生成完整计划，同步给双方。

```java
public class FragmentPlanner {

    /**
     * 生成碎片掉落计划。
     * @param disasterCategory 灾难类别（0=元素, 1=环境, 2=时空, 3=感知, 4=物理, 5=机制）
     * @param densityFactor 密度系数
     * @param seed 随机种子
     * @return 掉落计划列表
     */
    public List<FragmentDropPlan> generatePlan(int disasterCategory, float densityFactor, long seed) {
        Random rng = new Random(seed);
        List<FragmentDropPlan> plan = new ArrayList<>();

        int previewCount = 5;
        int collectCount = Math.round(25 * densityFactor);
        collectCount = Math.max(collectCount, 10);

        // 预告阶段碎片（1s 间隔）
        for (int i = 0; i < previewCount; i++) {
            plan.add(new FragmentDropPlan(
                IdGenerator.nextFragmentId(),
                generateType(rng, disasterCategory),
                generatePosition(rng),
                i * 1.0f,
                rng.nextLong()
            ));
        }

        // 收集阶段碎片（0.5s 间隔）
        for (int i = 0; i < collectCount; i++) {
            plan.add(new FragmentDropPlan(
                IdGenerator.nextFragmentId(),
                generateType(rng, disasterCategory),
                generatePosition(rng),
                previewCount + i * 0.5f,
                rng.nextLong()
            ));
        }

        return plan;
    }
}
```

### 碎片类型概率

| 碎片类型 | 基础概率 | 说明 |
|----------|---------|------|
| IceCrystal (冰晶 ★) | 55% | 常见 |
| Lava (熔岩 ★★) | 30% | 中等 |
| Rock (岩石 ★★★) | 15% | 稀有 |

> 灾难类别影响概率微调（元素类 +5% 冰晶/熔岩，感知类 -5% 冰晶/熔岩）。与客户端 `FragmentSystem.GenerateFragmentType` 逻辑一致。

### 碎片掉落位置

```
X 范围: [-10, 10]（建筑区域外）
Y 范围: [8, 13]（高空掉落）
```

> 若有建筑存在，掉落范围以建筑群中心调整，确保碎片落在建筑区域外。与客户端 `GenerateDropPosition` 逻辑一致。

## 二、ConflictResolver — 碎片接住冲突仲裁

服务器收到双方的 `C2S_FragmentCaught`，判定谁接住或同时接住。

```java
public class ConflictResolver {

    private static final long SIMULTANEOUS_WINDOW_MS = 100;

    // fragmentId → 第一个接住记录
    private final Map<Integer, CatchRecord> pendingCatches = new ConcurrentHashMap<>();

    private record CatchRecord(int playerId, long catchTime) {}

    /**
     * 处理碎片接住请求。
     * @return 判定结果（含 playerId 和 multiplier），null 表示等待第二人
     */
    public FragmentCatchResult onCatch(int fragmentId, int playerId, long catchTime) {
        if (pendingCatches.containsKey(fragmentId)) {
            CatchRecord first = pendingCatches.get(fragmentId);

            // 同一玩家重复触发
            if (first.playerId == playerId) return null;

            pendingCatches.remove(fragmentId);

            // 判定同时接住
            if (Math.abs(catchTime - first.catchTime) < SIMULTANEOUS_WINDOW_MS) {
                // 同时接住 ×3
                return new FragmentCatchResult(fragmentId, first.playerId, playerId, 3, true);
            } else {
                // 第一个接住的人获得碎片
                int winner = first.catchTime <= catchTime ? first.playerId : playerId;
                return new FragmentCatchResult(fragmentId, winner, -1, 1, false);
            }
        }

        // 第一个接住，暂存等待
        pendingCatches.put(fragmentId, new CatchRecord(playerId, catchTime));
        return null;  // 等待第二人或超时
    }

    /**
     * 超时清理：超过 100ms 窗口的暂存记录按单人接住处理。
     */
    public FragmentCatchResult checkTimeout(int fragmentId, long currentTime) {
        CatchRecord record = pendingCatches.get(fragmentId);
        if (record == null) return null;

        if (currentTime - record.catchTime >= SIMULTANEOUS_WINDOW_MS) {
            pendingCatches.remove(fragmentId);
            return new FragmentCatchResult(fragmentId, record.playerId, -1, 1, false);
        }
        return null;
    }
}
```

### 判定规则

| 场景 | 判定 | 倍率 |
|------|------|------|
| 单人接住（100ms 内无人竞争） | 接住者获得碎片 | ×1（地面）/ ×2（跳跃） |
| 两人 100ms 内同时接住 | 双方各获得碎片 | ×3 |
| 两人 100ms 外先后接住 | 先接住者获得碎片 | ×1 / ×2 |

> 同时接住判定窗口为 100ms，与客户端 `FragmentSystem.SIMULTANEOUS_WINDOW` 一致。服务器为唯一仲裁方。

### FragmentCatchResult

```java
public record FragmentCatchResult(
    int fragmentId,
    int winnerPlayerId,      // 获得碎片的玩家 ID
    int secondPlayerId,       // 同时接住时的第二玩家 ID，-1 表示无
    int multiplier,           // 倍率 (1/2/3)
    boolean isSimultaneous     // 是否同时接住
) {}
```

## 三、DisasterSelector — 灾难选型与种子生成

```java
public class DisasterSelector {

    /**
     * 选择本轮灾难并生成随机种子。
     * @param chapter 当前章节 (1-3)
     * @param section 当前节 (1-4)
     * @param round 当前轮 (1-3)
     * @return 灾难状态（含类型、参数、种子）
     */
    public DisasterState select(int chapter, int section, int round) {
        Random rng = new Random(System.nanoTime());

        // 根据章节限制灾难池范围
        int disasterId = pickDisasterId(rng, chapter);

        // 计算难度倍率
        float chapterMult = chapter == 1 ? 0.8f : chapter == 2 ? 1.0f : 1.2f;
        float roundMult = round == 1 ? 1.0f : round == 2 ? 1.3f : 1.6f;
        float difficultyMult = chapterMult * roundMult;

        // 生成随机种子（用于双方灾难效果同步）
        long seed = rng.nextLong();

        // 查找灾难参数
        DisasterParams params = loadDisasterParams(disasterId);

        return new DisasterState(disasterId, difficultyMult, seed, params);
    }
}
```

### 难度倍率

| 章节 | 倍率 | 轮次 | 倍率 | 综合 |
|------|------|------|------|------|
| 1 | ×0.8 | 1 | ×1.0 | ×0.8 |
| 2 | ×1.0 | 2 | ×1.3 | ×1.3 |
| 3 | ×1.2 | 3 | ×1.6 | ×1.92 |

> 与客户端 `GameProgress.ChapterMultiplier` / `RoundMultiplier` 完全一致。

### 灾难渐进强度时间轴

| 时间段 | 强度 | 说明 |
|--------|------|------|
| 0-5s | 30% | 灾害开始，轻微影响 |
| 5-10s | 60% | 灾害加剧，建筑开始承压 |
| 10-15s | 100% | 灾害全盛，最大压力 |
| 15-20s | 80% | 灾害消退，但仍有压力 |

> 双方各自按时间轴计算（确定性），不需实时同步。与客户端 `DisasterBase.CalculateIntensity` 一致。

## 四、DamageCalculator — 伤害计算

服务器权威计算所有伤害，客户端不自行扣血。

### 4.1 角色伤害

```java
public class DamageCalculator {

    /**
     * 计算灾难期间角色受到的环境伤害。
     * 基于确定性时间轴 + 建筑区域安全判定。
     *
     * @param player 玩家状态
     * @param disaster 灾难状态
     * @param buildings 建筑列表
     * @param deltaTime 时间增量
     * @return 实际伤害值（0 表示无伤害）
     */
    public int calculatePlayerDamage(PlayerState player, DisasterState disaster,
                                       List<BuildingState> buildings, float deltaTime) {
        // 1. 判定角色是否在建筑安全区域内
        if (isInBuildingZone(player.getPosition(), buildings)) {
            return 0;
        }

        // 2. 计算灾难渐进强度（确定性时间轴）
        float intensity = calculateDisasterIntensity(disaster);

        // 3. 计算基础 DPS
        float baseDPS = disaster.getParams().getBaseDPS();

        // 4. 判定角色是否在灾难影响范围内
        float distToDisaster = Vector2.distance(player.getPosition(), disaster.getParams().getPosition());
        if (distToDisaster > disaster.getParams().getRange()) {
            return 0;
        }

        // 5. 濒死保护
        float damageMultiplier = 1.0f;
        if (player.getHp() <= 30) {
            damageMultiplier *= 0.7f;  // 濒死减伤 30%
        }

        // 6. 计算最终伤害
        float damage = baseDPS * intensity * damageMultiplier * deltaTime;
        return (int) Math.ceil(damage);
    }

    /**
     * 灾难渐进强度时间轴。
     * 0-5s: 30%, 5-10s: 60%, 10-15s: 100%, 15-20s: 80%
     */
    private float calculateDisasterIntensity(DisasterState disaster) {
        float elapsed = disaster.getElapsedTime();
        if (elapsed < 5f) return 0.3f;
        if (elapsed < 10f) return 0.6f;
        if (elapsed < 15f) return 1.0f;
        return 0.8f;
    }
}
```

### 4.2 建筑伤害

```java
/**
 * 计算灾难对建筑的伤害。
 */
public float calculateBuildingDamage(BuildingState building, DisasterState disaster, float deltaTime) {
    float intensity = calculateDisasterIntensity(disaster);
    float baseDPS = disaster.getParams().getBaseDPS();

    // 查找抗性等级
    float resistanceMultiplier = getResistanceMultiplier(building, disaster);

    return baseDPS * intensity * resistanceMultiplier * deltaTime;
}
```

## 五、ShelterCalculator — 庇护能量计算

```java
public class ShelterCalculator {

    private static final float MAX_ENERGY = 100f;
    private static final float RECOVERY_RATE = 20f;    // +20/s 在范围内
    private static final float CONSUMPTION_RATE = 33f;  // -33/s 超出范围
    private static final float SHELTER_DISTANCE = 3f;   // 3 格
    private static final float BUFFER_TIME = 3f;        // 3 秒缓冲

    /**
     * 更新玩家庇护能量。
     */
    public void updateEnergy(PlayerState aqua, PlayerState ignis, float deltaTime) {
        float distance = Vector2.distance(aqua.getPosition(), ignis.getPosition());
        boolean inRange = distance <= SHELTER_DISTANCE;

        updateSingleEnergy(aqua, inRange, deltaTime);
        updateSingleEnergy(ignis, inRange, deltaTime);
    }

    private void updateSingleEnergy(PlayerState player, boolean inRange, float deltaTime) {
        float energy = player.getShelterEnergy();

        if (inRange) {
            energy = Math.min(MAX_ENERGY, energy + RECOVERY_RATE * deltaTime);
        } else {
            energy = Math.max(0f, energy - CONSUMPTION_RATE * deltaTime);
        }

        player.setShelterEnergy(energy);

        // 能量耗尽 → 缓冲期 → 扣血
        if (energy <= 0f) {
            if (player.getBufferTimer() <= 0f && !player.isBuffering()) {
                player.startBuffering(BUFFER_TIME);
            } else if (player.isBufferExpired()) {
                // 缓冲期结束，由 DamageCalculator 计算环境伤害
            }
        }
    }
}
```

### 庇护能量参数

| 参数 | 值 | 说明 |
|------|------|------|
| 最大能量 | 100 | 双方独立 |
| 范围内恢复 | +20/s | 3 格内 |
| 超范围消耗 | -33/s | 超出 3 格 |
| 庇护距离 | 3 格 | 碎片收集阶段为 5 格 |
| 缓冲时间 | 3 秒 | 能量耗尽后不立即扣血 |

> 与客户端 `ShelterSystem` 参数一致。服务器计算后通过 `S2C_MidFreqState` 下发能量值。

## 六、BuildingManager — 建筑状态管理

```java
public class BuildingManager {

    private final Map<Integer, BuildingState> buildings = new ConcurrentHashMap<>();
    private int nextBuildingId = 1;

    /**
     * 放置建筑。
     * @return 建筑状态（含分配的 buildingId），null 表示放置失败
     */
    public BuildingState place(int playerId, int buildingType, int material, int gridX, int gridY) {
        // 验证网格占用
        if (isGridOccupied(gridX, gridY)) return null;

        BuildingState building = new BuildingState(
            nextBuildingId++, buildingType, material, gridX, gridY,
            getMaxHP(buildingType, material)
        );
        buildings.put(building.getBuildingId(), building);
        return building;
    }

    /**
     * 建筑受伤。
     */
    public void applyDamage(int buildingId, float damage) {
        BuildingState building = buildings.get(buildingId);
        if (building == null) return;

        building.setHp(building.getHp() - damage);
        if (building.getHp() <= 0f) {
            buildings.remove(buildingId);
            // 触发摧毁事件
        }
    }

    /**
     * 获取所有建筑（用于伤害计算和快照）。
     */
    public List<BuildingState> getAllBuildings() {
        return new ArrayList<>(buildings.values());
    }

    /**
     * 同步建筑 HP（修整阶段校正）。
     */
    public List<BuildingState> syncBuildingHP() {
        return getAllBuildings();
    }
}
```

## 七、TalentPool — 天赋池管理

```java
public class TalentPool {

    private static final int TALENT_PICK_COUNT = 3;  // 3 选 1

    /**
     * 为玩家生成天赋 3 选 1 选项。
     */
    public List<TalentData> rollOptions(int playerId, int globalRound) {
        Random rng = new Random(System.nanoTime() + playerId * 1000L + globalRound);

        List<TalentData> pool = loadTalentPool();
        Collections.shuffle(pool, rng);

        List<TalentData> options = new ArrayList<>();
        for (int i = 0; i < TALENT_PICK_COUNT && i < pool.size(); i++) {
            options.add(pool.get(i));
        }
        return options;
    }
}
```

## 八、AIController — 断线 AI 接管

```java
public class AIController {

    private static final float TICK_INTERVAL_SEC = 0.05f;  // 20Hz
    private static final float FOLLOW_DISTANCE = 2.5f;
    private static final float MOVE_SPEED = 4.0f;  // 4 格/s

    /**
     * AI 控制掉线玩家。
     * 保守策略：跟随存活玩家、保持庇护距离、不主动行动。
     */
    public void onTick(PlayerState aiPlayer, PlayerState partner, GameRoom room) {
        // 1. 移动：朝向伙伴，保持 2 格距离
        Vector2 aiPos = aiPlayer.getPosition();
        Vector2 partnerPos = partner.getPosition();
        float distance = Vector2.distance(aiPos, partnerPos);

        if (distance > FOLLOW_DISTANCE) {
            // 朝伙伴移动
            Vector2 direction = Vector2.subtract(partnerPos, aiPos).normalize();
            aiPlayer.setPosition(Vector2.add(aiPos, direction.multiply(MOVE_SPEED * TICK_INTERVAL_SEC)));
        }

        // 2. AI 不捡碎片、不建造、不放技能（保守行为）

        // 3. 广播 AI 玩家状态
        room.broadcast(new S2C_HighFreqState(aiPlayer));
    }
}
```

### AI 行为规则

| 行为 | 说明 |
|------|------|
| 移动 | 跟随存活玩家，保持 2 格庇护距离 |
| 碎片 | ❌ 不捡碎片 |
| 建造 | ❌ 不放置建筑 |
| 技能 | ❌ 不释放技能 |
| 受伤 | ✅ 正常受伤（服务器计算） |
| 状态同步 | ✅ 服务器广播 AI 角色高频状态 |

> 与 `断线重连.md` 中的断线处理时间轴配合使用。AI 接管后 120 秒内若玩家未重连，游戏结束。
