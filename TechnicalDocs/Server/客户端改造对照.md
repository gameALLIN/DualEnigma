## 一、改造总览

服务器实现后，Unity 客户端需要以下改造。核心原则：**所有权威逻辑移至服务器，客户端只负责输入、预测、渲染**。

### 改造优先级

| 优先级 | 含义 | 阶段 |
|--------|------|------|
| P0 | 必须先做，阻塞通信链路 | Phase 0-1 |
| P1 | 核心玩法，做完即可联机对战 | Phase 2-3 |
| P2 | 辅助系统，完善体验 | Phase 4 |

## 二、逐系统改造

### 2.1 NetworkSystem (P0)

**当前状态**: 空壳实现，`SendHighFrequencyState` / `SendMidFrequencyState` / `SendKeyEvent` 三个方法无实际逻辑。

**改造内容**:

| 改造项 | 说明 |
|--------|------|
| WebSocket 客户端 | 替换为 `ClientWebSocket`，实现连接、断开、重连 |
| 消息收发 | 实现 JSON 序列化/反序列化 + 消息发送队列 |
| 消息接收分发 | 收到 S2C 消息后路由到对应系统 |
| 心跳发送 | 1Hz 应用层心跳 |
| 接口扩展 | `INetworkSystem` 增加消息注册/监听机制 |

**新增接口方法**:
```csharp
// 注册 S2C 消息处理器
void RegisterHandler<T>(Action<T> handler) where T : class;
// 发送 C2S 消息
void Send<T>(T message) where T : class;
```

### 2.2 GameStateMachine (P0)

**当前状态**: 客户端自跑 `Update` 计时器，自主切换 `NextPhase()`。

**改造内容**:

| 当前行为 | 改造后 |
|----------|--------|
| `Update()` 自跑倒计时 | ❌ 移除，客户端不自跑计时器 |
| `NextPhase()` 自主切换 | ❌ 移除，由服务器驱动 |
| `SetPhase()` 被动调用 | ✅ 保留，接收 `S2C_PhaseChange` 后调用 |
| — | ✅ 新增：用 `phaseEndTime` 校准本地计时器 |

**改造后流程**:
```
收到 S2C_PhaseChange → SetPhase(phase) → 用 phaseEndTime 校准 → 发布 PhaseChangedEvent
```

### 2.3 CharacterController (P1)

**当前状态**: `Move()` 直接改 Rigidbody2D 速度，无本地/远程区分。

**改造内容**:

| 改造项 | 说明 |
|--------|------|
| `isLocalPlayer` 标记 | 区分本地角色和远程角色 |
| 本地角色：输入驱动 | `Move()` / `Jump()` 仍本地执行（预测），同时发送 `C2S_HighFreqState` |
| 远程角色：插值驱动 | 不走 `Move()`，从插值缓冲区读位置做 `Vector2.Lerp` |
| `OnTriggerEnter2D` 碎片收集 | 本地角色发 `C2S_FragmentCaught`，等待 `S2C_FragmentResult` 后执行 |
| 动画状态同步 | `animState` / `facing` 通过高频状态包同步 |

**改造后 `Move()` 示例**:
```csharp
public void Move(float direction)
{
    if (!isLocalPlayer) return;  // 远程角色不接受输入

    // 本地预测
    _rb.velocity = new Vector2(direction * speed, _rb.velocity.y);

    // 发送高频状态给服务器
    INetworkSystem network = ServiceLocator.Get<INetworkSystem>();
    network.Send(new C2S_HighFreqState {
        position = transform.position,
        velocity = _rb.velocity,
        animState = CurrentAnimState,
        facing = FacingRight
    });
}
```

**新增远程角色插值**:
```csharp
// 远程角色每帧插值
public void InterpolatePosition(Vector2 targetPos, float interpolationBuffer)
{
    if (isLocalPlayer) return;
    _rb.MovePosition(Vector2.Lerp(transform.position, targetPos, interpolationBuffer));
}
```

### 2.4 FragmentSystem (P1)

**当前状态**: 本地生成掉落计划、本地判定同时接住。

**改造内容**:

| 当前行为 | 改造后 |
|----------|--------|
| `GenerateDropPlan()` | ❌ 移除，由服务器生成 |
| `ExecuteDropPlan()` | ✅ 保留，接收 `S2C_FragmentDropPlan` 后执行 |
| `OnFragmentCollected()` 本地判定 | ❌ 移除，改为发 `C2S_FragmentCaught` 给服务器 |
| `_pendingCollects` 本地暂存 | ❌ 移除，由服务器 `ConflictResolver` 仲裁 |
| 收集逻辑 | ✅ 接收 `S2C_FragmentResult` 后执行（添加碎片/播放特效） |
| `Random.Range` 被动技能触发 | ⚠️ 需改为种子化 RNG 或由服务器判定 |

**改造后 `OnFragmentCollected` 示例**:
```csharp
public void OnFragmentCollected(int fragmentId, byte playerId, bool isJumping)
{
    if (!isLocalPlayer) return;

    // 不再本地判定，直接发给服务器
    INetworkSystem network = ServiceLocator.Get<INetworkSystem>();
    network.Send(new C2S_FragmentCaught { fragmentId = fragmentId });
}

// 接收服务器判定结果
void OnFragmentResult(S2C_FragmentResult result)
{
    // 执行收集逻辑
    EventBus.Instance.Publish(new FragmentCollectedEvent {
        fragmentId = result.fragmentId,
        playerId = (byte)result.playerId,
        multiplier = result.multiplier
    });
    ReleaseFragment(result.fragmentId);
}
```

### 2.6 ShelterSystem (P1)

**当前状态**: `DealDamage` / `Heal` 本地直接修改 HP。

**改造内容**:

| 当前行为 | 改造后 |
|--------|--------|
| `DealDamage()` 本地扣血 | ❌ 移除，HP 由服务器通过 `S2C_MidFreqState` 下发 |
| `Heal()` 本地加血 | ❌ 移除，HP 由服务器通过 `S2C_MidFreqState` 下发 |
| 能量计算 | ✅ 保留本地计算（确定性，基于位置距离），服务器 10Hz 校正 |
| 建筑区域安全判定 | ✅ 保留本地判定（确定性） |
| `SyncHPToCharacter()` | ✅ 保留，但数据源从服务器中频状态包获取 |

**改造后 HP 更新**:
```csharp
// 从服务器中频状态包更新 HP
void OnMidFreqState(S2C_MidFreqState state)
{
    foreach (var playerState in state.players)
    {
        if (playerState.playerId == 0)
            _aquaHP = playerState.hp;
        else
            _ignisHP = playerState.hp;

        SyncHPToCharacter(playerState.playerId == 0 ? CharacterType.Aqua : CharacterType.Ignis);
    }
}
```

### 2.10 EventBus — NetworkEventBridge (P1)

**当前状态**: `EventBus` 是纯本地事件，没有网络穿透。

**需要新增** `NetworkEventBridge` 层，桥接本地事件与网络消息：

```
本地事件 → 判断是否需要同步 → 序列化为 C2S 消息 → INetworkSystem.Send()
                                                    ↓
收到 S2C 消息 → 反序列化 → 还原为本地事件 → EventBus.Publish()
```

**桥接映射表**:

| 本地事件 | C2S 消息 | S2C 消息 | 远端还原事件 |
|----------|---------|---------|-------------|
| `FragmentCollectedEvent` | `C2S_FragmentCaught` | `S2C_FragmentResult` | `FragmentCollectedEvent` |
| `BuildingPlacedEvent` | `C2S_BuildingPlace` | `S2C_BuildingUpdate` | `BuildingPlacedEvent` |
| `SkillActivatedEvent` | `C2S_SkillActivate` | `S2C_SkillResult` | `SkillActivatedEvent` |
| `TalentSelectedEvent` | `C2S_TalentSelect` | `S2C_TalentSelected` | `TalentSelectedEvent` |
| `PhaseChangedEvent` | — | `S2C_PhaseChange` | `PhaseChangedEvent` |

**设计原则**:
- 不是所有 `EventBus` 事件都需要网络同步（如 `PlayerDamagedEvent` 由中频状态包覆盖）
- `NetworkEventBridge` 只处理需要跨端的 关键事件
- 本地事件先发 C2S，收到 S2C 确认后再 `Publish` 到 `EventBus`，避免本地重复执行

## 三、改造总结

| 系统 | 优先级 | 核心变化 |
|------|--------|---------|
| NetworkSystem | P0 | 空壳 → WebSocket 客户端 |
| GameStateMachine | P0 | 自主驱动 → 服务器被动驱动 |
| CharacterController | P1 | 单一模式 → 本地/远程双模式 |
| FragmentSystem | P1 | 本地仲裁 → 服务器仲裁 |
| DisasterSystem | P1 | 自选灾难 → 服务器选型 |
| ShelterSystem | P1 | 本地 HP → 服务器权威 HP |
| BuildingSystem | P2 | 本地管理 → 服务器验证 |
| SkillSystem | P2 | 本地执行 → 服务器判定 |
| TalentSystem | P2 | 本地抽选 → 服务器推送 |
| EventBus | P1 | 纯本地 → NetworkEventBridge 桥接 |
