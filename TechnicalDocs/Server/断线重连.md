## 一、断线处理时间轴

| 阶段 | 时间 | 服务器行为 | 客户端行为 |
|------|------|----------|-----------|
| 即时断线 | 0s | 检测到心跳超时（5s），标记断线 | 显示"正在重连..." |
| 重连窗口 | 0-30s | 保持房间状态，等待重连 | 倒计时显示 |
| AI 接管 | 30s | 启动 AIController 控制掉线玩家 | 显示"队友已断开，AI 接管" |
| 最终超时 | 120s | 关闭房间，判定失败 | 游戏结束 |

### 断线检测机制

```
心跳检测:
  - 服务器和客户端每 1 秒互发一次应用层心跳
  - 连续 5 秒未收到对方心跳 → 判定断线
  - WebSocket Ping/Pong 作为传输层辅助检测

为什么 5 秒而非 30 秒:
  - 5 秒检测确保快速感知断线
  - 30 秒是"游戏内重连窗口"（允许玩家重新连接的宽限时间）
  - 检测断线（5s）≠ 重连超时（30s）≠ 最终超时（120s）
```

| 时间节点 | 含义 | 触发动作 |
|----------|------|----------|
| 5s | 心跳超时，判定断线 | 通知对方 `S2C_OpponentDisconnect(state=waiting)` |
| 30s | 重连窗口超时 | 启动 AI 接管，通知 `S2C_OpponentDisconnect(state=aiTakeover)` |
| 120s | 最终超时 | 游戏结束，通知 `S2C_OpponentDisconnect(state=timeout)` |

## 二、重连全量快照

重连成功后，服务器发送 `S2C_ReconnectSnapshot` 恢复客户端到与服务器完全一致的状态。

### 2.1 快照结构

```java
public class GameSnapshot {
    // 游戏进度
    private int chapter;              // 当前章节 (1-3)
    private int section;               // 当前节 (1-4)
    private int round;                 // 当前轮 (1-3)
    private GamePhase currentPhase;    // 当前游戏阶段
    private long phaseEndTime;         // 阶段结束时间戳
    private int score;                 // 累计得分

    // 角色状态
    private PlayerState[] players;     // [0]=Aqua, [1]=Ignis

    // 建筑状态
    private List<BuildingState> buildings;

    // 碎片状态
    private List<FragmentState> fragments;  // 场上存活碎片

    // 天赋/技能
    private List<TalentData> talents;   // 已选天赋列表
    private List<SkillState> skills;    // 技能状态（ID/冷却/次数）

    // 灾难状态（仅灾害冲击阶段）
    private DisasterState disaster;     // 可能为 null

    // 快照时间戳
    private long snapshotTimestamp;
}
```

### 2.2 快照内容

| 恢复内容 | 字段 | 说明 |
|----------|------|------|
| 角色状态 | players[] | 双方 HP、能量、位置、速度、携带碎片、动画状态 |
| 建筑状态 | buildings[] | 所有建筑的类型/材料/当前HP/网格位置 |
| 游戏阶段 | currentPhase + phaseEndTime | 确保客户端恢复到正确的阶段和时间 |
| 碎片状态 | fragments[] | 场上所有未消失碎片的位置和类型 |
| 天赋/技能 | talents[] + skills[] | 全局天赋选择记录和技能状态 |
| 灾难状态 | disaster | 若处于灾害冲击阶段，需恢复灾难模拟（含种子） |
| 游戏进度 | chapter/section/round/score | 全局游戏进度信息 |

## 三、重连流程

```
客户端 --C2S_Connect(roomCode, playerId)--> 服务器

服务器:
  1. 查找 roomCode 对应的 GameRoom
  2. 验证 playerId 是否匹配
  3. 恢复 ClientSession
  4. 停止 AIController（若正在接管）
  5. 生成 GameSnapshot
  6. 发送 S2C_ReconnectSnapshot

客户端:
  1. 接收快照
  2. 恢复所有本地状态:
     ├─ 角色位置/HP/能量/携带碎片
     ├─ 建筑列表
     ├─ 场上碎片
     ├─ 当前阶段 + 剩余时间
     ├─ 已选天赋
     └─ 技能冷却状态
  3. 恢复正常游戏循环
  4. 恢复高频状态发送
```

### 重连关键约束

| 约束 | 说明 |
|------|------|
| 重连不惩罚 | 玩家重连后恢复控制，无额外惩罚 |
| 房间保持 | 断线期间房间不销毁，等待重连或超时 |
| AI 状态接管 | AI 接管期间的状态变更已在服务器权威状态中体现，重连后直接同步 |
| 快照可靠传输 | `S2C_ReconnectSnapshot` 通过 WebSocket 可靠传输（TCP 保证有序） |

## 四、AI 接管期间的行为

AI 接管期间（30s 后 ~ 120s 超时前），服务器同时控制两个角色：

| 行为 | 说明 |
|------|------|
| AI 角色移动 | 服务器本地模拟 AI 角色移动（跟随存活玩家、保持 2 格庇护距离） |
| AI 角色高频状态 | 服务器正常发送 AI 角色的高频状态包给客户端 |
| AI 角色不使用技能 | AI 不触发技能释放事件（保守行为，避免误操作） |
| AI 角色不捡碎片 | AI 不触发碎片接住事件 |
| AI 角色不建造 | AI 不触发建筑放置事件 |
| AI 角色受伤 | 服务器正常计算伤害（确定性时间轴） |

> AI 行为保守（不主动行动），避免因 AI 误操作导致游戏失败。与 `权威逻辑.md` §八 AIController 配合使用。

## 五、断线状态通知

服务器在断线各阶段向存活玩家发送 `S2C_OpponentDisconnect`：

| 阶段 | state 值 | 客户端显示 |
|------|----------|-----------|
| 心跳超时（5s） | `waiting` | "队友已断开，等待重连...（30s）" |
| 重连窗口超时（30s） | `aiTakeover` | "队友未重连，AI 已接管" |
| 最终超时（120s） | `timeout` | "队友离线超时，游戏结束" |
| 重连成功 | — | 正常恢复，无通知（直接收到快照） |
