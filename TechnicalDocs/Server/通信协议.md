## 一、消息格式

所有消息为 JSON，统一结构：

```json
{
  "type": "C2S_HighFreqState",
  "timestamp": 1691908800000,
  "playerId": 0,
  "data": { ... }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| type | String | 消息类型枚举名，对应 `MessageType` |
| timestamp | long | 客户端发送时间戳（毫秒），用于延迟计算 |
| playerId | int | 发送方玩家 ID（0=Aqua, 1=Ignis） |
| data | Object | 消息体，结构由具体消息类型决定 |

> **S2C 消息** 的 `playerId` 字段表示消息所指玩家的 ID（如 `S2C_HighFreqState` 中 `playerId` 为被同步的对方玩家 ID）。

## 二、消息类型总览

### 2.1 客户端 → 服务器 (C2S)

| 消息类型 | 触发时机 | 频率 | data 内容 |
|----------|---------|------|-----------|
| `C2S_Connect` | 客户端启动 | 一次性 | `roomCode` (可选) |
| `C2S_HighFreqState` | 本地角色状态变化 | 20Hz | `position` {x,y}, `velocity` {x,y}, `animState`, `facing` |
| `C2S_FragmentCaught` | 角色碰到碎片 | 事件驱动 | `fragmentId` |
| `C2S_BuildingPlace` | 玩家放置建筑 | 事件驱动 | `buildingType`, `material`, `gridX`, `gridY` |
| `C2S_BuildingRemove` | 玩家拆除建筑 | 事件驱动 | `buildingId` |
| `C2S_Synthesize` | 玩家请求合成 | 事件驱动 | `fragmentIds` [] |
| `C2S_SkillActivate` | 玩家释放技能 | 事件驱动 | `skillId`, `targetPos` {x,y} |
| `C2S_TalentSelect` | 玩家选择天赋 | 事件驱动 | `talentId` |
| `C2S_Heartbeat` | 心跳 | 1Hz | 空 |

### 2.2 服务器 → 客户端 (S2C)

| 消息类型 | 触发时机 | 频率 | data 内容 |
|----------|---------|------|-----------|
| `S2C_ConnectAck` | 连接成功 | 一次性 | `playerId`, `roomCode` |
| `S2C_GameStart` | 两人就绪 | 一次性 | `chapter`, `section`, `round` |
| `S2C_PhaseChange` | 阶段切换 | 7次/轮 | `phase`, `durationMs`, `phaseEndTime` |
| `S2C_HighFreqState` | 转发对方状态 | 20Hz | `playerId`, `position`, `velocity`, `animState`, `facing` |
| `S2C_MidFreqState` | HP/能量同步 | 10Hz | `players` [{playerId, hp, shelterEnergy, carriedFragments}] |
| `S2C_FragmentDropPlan` | 碎片掉落计划 | 1次/阶段 | `plan` [{fragmentId, type, position, dropTime, seed}] |
| `S2C_FragmentResult` | 碎片接住判定 | 事件驱动 | `fragmentId`, `playerId`, `multiplier` |
| `S2C_DisasterStart` | 灾难开始 | 1次/轮 | `disasterId`, `difficultyMultiplier`, `randomSeed`, `params` |
| `S2C_DisasterEnd` | 灾难结束 | 1次/轮 | 空 |
| `S2C_BuildingUpdate` | 建筑变更 | 事件驱动 | `action` (place/destroy/sync), `building` {...} |
| `S2C_SkillResult` | 技能判定结果 | 事件驱动 | `skillId`, `playerId`, `targetPos`, `effects` [...] |
| `S2C_TalentOptions` | 天赋选择推送 | 1次/升级阶段 | `options` [{talentId, name, ...}] |
| `S2C_TalentSelected` | 对方天赋选择通知 | 事件驱动 | `playerId`, `talentId` |
| `S2C_ReconnectSnapshot` | 重连全量同步 | 一次性 | 完整快照（详见 `断线重连.md`） |
| `S2C_OpponentDisconnect` | 对方断线 | 事件驱动 | `state` (waiting/aiTakeover/timeout) |
| `S2C_HeartbeatAck` | 心跳回应 | 1Hz | `serverTimestamp` |

## 四、C2S 消息详情

### 4.1 C2S_Connect

```json
{
  "type": "C2S_Connect",
  "timestamp": 1691908800000,
  "playerId": -1,
  "data": {
    "roomCode": "ABC123"
  }
}
```

> `playerId` 为 -1 表示尚未分配。`roomCode` 可选，为空则自动匹配。

### 4.2 C2S_HighFreqState

```json
{
  "type": "C2S_HighFreqState",
  "timestamp": 1691908800050,
  "playerId": 0,
  "data": {
    "position": { "x": 3.5, "y": 1.0 },
    "velocity": { "x": 4.0, "y": 0.0 },
    "animState": "Run",
    "facing": true
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| position.x / y | float | 角色世界坐标 |
| velocity.x / y | float | 角色速度向量 |
| animState | String | 动画状态枚举（Idle/Run/Jump/Fall/Hurt） |
| facing | bool | 朝向（true=右, false=左） |

### 4.3 C2S_FragmentCaught

```json
{
  "type": "C2S_FragmentCaught",
  "timestamp": 1691908801000,
  "playerId": 0,
  "data": {
    "fragmentId": 42
  }
}
```

### 4.4 C2S_BuildingPlace

```json
{
  "type": "C2S_BuildingPlace",
  "timestamp": 1691908802000,
  "playerId": 1,
  "data": {
    "buildingType": 1,
    "material": 2,
    "gridX": 5,
    "gridY": 3
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| buildingType | int | 建筑类型枚举值 |
| material | int | 材料类型枚举值 |
| gridX / gridY | int | 网格坐标 |

## 五、S2C 消息详情

### 5.1 S2C_ConnectAck

```json
{
  "type": "S2C_ConnectAck",
  "timestamp": 1691908800000,
  "playerId": 0,
  "data": {
    "playerId": 0,
    "roomCode": "ABC123"
  }
}
```

### 5.2 S2C_GameStart

```json
{
  "type": "S2C_GameStart",
  "timestamp": 1691908800100,
  "playerId": -1,
  "data": {
    "chapter": 1,
    "section": 1,
    "round": 1
  }
}
```

### 5.3 S2C_PhaseChange

```json
{
  "type": "S2C_PhaseChange",
  "timestamp": 1691908800200,
  "playerId": -1,
  "data": {
    "phase": "FragmentCollect",
    "durationMs": 15000,
    "phaseEndTime": 1691908815200
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| phase | String | 阶段枚举名（Preview/FragmentCollect/DisasterPreview/Build/DisasterImpact/Rest/Upgrade） |
| durationMs | int | 阶段时长（毫秒） |
| phaseEndTime | long | 阶段结束的服务器时间戳（毫秒），客户端用于校正本地计时器 |

### 5.4 S2C_HighFreqState

```json
{
  "type": "S2C_HighFreqState",
  "timestamp": 1691908800050,
  "playerId": 1,
  "data": {
    "playerId": 1,
    "position": { "x": 7.0, "y": 1.0 },
    "velocity": { "x": 0.0, "y": 0.0 },
    "animState": "Idle",
    "facing": false
  }
}
```

> `playerId` 为对方玩家的 ID。客户端收到后更新远程角色的插值缓冲区。

### 5.5 S2C_MidFreqState

```json
{
  "type": "S2C_MidFreqState",
  "timestamp": 1691908800100,
  "playerId": -1,
  "data": {
    "players": [
      { "playerId": 0, "hp": 85, "shelterEnergy": 75, "carriedFragments": [0, 0, 1] },
      { "playerId": 1, "hp": 92, "shelterEnergy": 100, "carriedFragments": [2] }
    ]
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| hp | int | 当前生命值 |
| shelterEnergy | int | 庇护能量值（0-100） |
| carriedFragments | int[] | 携带碎片类型列表 |

### 5.6 S2C_FragmentDropPlan

```json
{
  "type": "S2C_FragmentDropPlan",
  "timestamp": 1691908800200,
  "playerId": -1,
  "data": {
    "plan": [
      { "fragmentId": 0, "type": 0, "position": {"x": -5.0, "y": 12.0}, "dropTime": 0.0, "seed": 12345 },
      { "fragmentId": 1, "type": 1, "position": {"x": 3.0, "y": 11.0}, "dropTime": 1.0, "seed": 67890 }
    ]
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| fragmentId | int | 碎片唯一 ID |
| type | int | 碎片类型（0=冰晶, 1=熔岩, 2=岩石） |
| position | {x, y} | 掉落位置 |
| dropTime | float | 相对于阶段开始的掉落时间（秒） |
| seed | long | 碎片物理掉落随机种子 |

### 5.7 S2C_FragmentResult

```json
{
  "type": "S2C_FragmentResult",
  "timestamp": 1691908801000,
  "playerId": -1,
  "data": {
    "fragmentId": 42,
    "playerId": 0,
    "multiplier": 3,
    "isSimultaneous": true
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| fragmentId | int | 碎片 ID |
| playerId | int | 接住碎片的玩家 ID（同时接住时为第一个接住的玩家） |
| multiplier | int | 倍率（1=普通, 2=跳跃接住, 3=同时接住） |
| isSimultaneous | bool | 是否同时接住（双方各获得一份碎片） |

### 5.10 S2C_BuildingUpdate

```json
{
  "type": "S2C_BuildingUpdate",
  "timestamp": 1691908800400,
  "playerId": -1,
  "data": {
    "action": "place",
    "building": {
      "buildingId": 7,
      "buildingType": 1,
      "material": 2,
      "gridX": 5,
      "gridY": 3,
      "currentHP": 100.0
    }
  }
}
```

| action 值 | 说明 |
|-----------|------|
| `place` | 新建筑放置，`building` 含完整信息 |
| `destroy` | 建筑被摧毁，`building.buildingId` 标识被摧毁的建筑 |
| `sync` | 修整阶段批量同步，`building` 为建筑列表（`buildings` 字段） |

### 5.14 S2C_OpponentDisconnect

```json
{
  "type": "S2C_OpponentDisconnect",
  "timestamp": 1691908800800,
  "playerId": -1,
  "data": {
    "state": "waiting"
  }
}
```

| state 值 | 说明 |
|----------|------|
| `waiting` | 对方断线，等待重连（0-30s） |
| `aiTakeover` | AI 已接管对方角色（30s 后） |
| `timeout` | 最终超时，游戏结束（120s 后） |

### 5.15 S2C_HeartbeatAck

```json
{
  "type": "S2C_HeartbeatAck",
  "timestamp": 1691908800900,
  "playerId": -1,
  "data": {
    "serverTimestamp": 1691908800900
  }
}
```

> 客户端用 `serverTimestamp` 计算往返延迟（RTT = 当前时间 - 发送时间）。
