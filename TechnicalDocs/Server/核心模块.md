## 二、MessageRouter — 消息路由

根据 `MessageType` 分发到对应处理器。

```java
@Component
public class MessageRouter {

    private final Map<MessageType, MessageHandler> handlers = new EnumMap<>();

    public void route(ClientSession session, Message msg) {
        MessageHandler handler = handlers.get(msg.getType());
        if (handler != null) {
            handler.handle(session, msg);
        }
    }
}

// 处理器接口
public interface MessageHandler {
    void handle(ClientSession session, Message msg);
}
```

**路由表**:

| MessageType | 处理器 | 目标 |
|-------------|--------|------|
| C2S_CONNECT | ConnectHandler | RoomManager.onPlayerConnect() |
| C2S_HIGH_FREQ_STATE | HighFreqHandler | GameRoom 转发给对方 |
| C2S_FRAGMENT_CAUGHT | FragmentHandler | ConflictResolver.onCatch() |
| C2S_BUILDING_PLACE | BuildingHandler | BuildingManager.place() |
| C2S_BUILDING_REMOVE | BuildingHandler | BuildingManager.remove() |
| C2S_SYNTHESIZE | SynthesizeHandler | SynthesisValidator.validate() |
| C2S_SKILL_ACTIVATE | SkillHandler | SkillExecutor.execute() |
| C2S_TALENT_SELECT | TalentHandler | TalentPool.select() |
| C2S_HEARTBEAT | HeartbeatHandler | HeartbeatManager.onHeartbeat() |

## 五、GameTickScheduler — 逻辑帧调度器

服务器以 20Hz 固定逻辑帧驱动权威逻辑。

```java
public class GameTickScheduler {

    private static final long TICK_INTERVAL_MS = 50;  // 20Hz
    private final ScheduledExecutorService scheduler;
    private ScheduledFuture<?> tickTask;

    // 启动逻辑帧循环
    public void start(GameRoom room) {
        tickTask = scheduler.scheduleAtFixedRate(() -> {
            room.getGameManager().onTick();
        }, 0, TICK_INTERVAL_MS, TimeUnit.MILLISECONDS);
    }

    // 停止
    public void stop() {
        if (tickTask != null) tickTask.cancel(false);
    }
}
```

**每 Tick 执行内容**:

```
onTick():
  1. GameStateMachine.onTick()        — 阶段计时器推进
  2. ShelterCalculator.update()       — 庇护能量计算
  3. DamageCalculator.update()         — 伤害计算（仅 DisasterImpact 阶段）
  4. ConflictResolver.checkTimeouts()  — 碎片接住超时判定
  5. 每 5 个 Tick (10Hz):              — 发送 S2C_MidFreqState
  6. AIController.onTick() (若需AI接管) — AI 控制
```

## 六、GameStateMachine — 权威阶段计时器

服务器独占阶段推进，客户端被动接收 `S2C_PhaseChange`。

```java
public class GameStateMachine {

    private static final int[] PHASE_DURATIONS_MS = {
        5000,   // Preview
        15000,  // FragmentCollect
        5000,   // DisasterPreview
        20000,  // Build
        20000,  // DisasterImpact
        10000,  // Rest
        15000,  // Upgrade
    };

    private GamePhase currentPhase = GamePhase.Preview;
    private long phaseEndTime;        // 阶段结束的服务器时间戳（毫秒）
    private boolean running = false;

    // 每个 Tick 调用
    public void onTick(long currentTime) {
        if (!running) return;
        if (currentTime >= phaseEndTime) {
            nextPhase();
        }
    }

    // 切换阶段
    private void nextPhase() {
        int nextIndex = (currentPhase.ordinal() + 1) % GamePhase.values().length;
        setPhase(GamePhase.values()[nextIndex]);
    }

    // 设置阶段并通知
    private void setPhase(GamePhase phase) {
        currentPhase = phase;
        phaseEndTime = System.currentTimeMillis() + PHASE_DURATIONS_MS[phase.ordinal()];

        // 触发阶段回调
        onPhaseEnter(phase);

        // 广播给双方客户端
        broadcast(new S2C_PhaseChange(phase, PHASE_DURATIONS_MS[phase.ordinal()], phaseEndTime));
    }

    // 阶段进入回调（由 GameManager 注册）
    private void onPhaseEnter(GamePhase phase) {
        switch (phase) {
            case Preview -> generateRoundContent();      // 选灾难 + 生成碎片计划
            case FragmentCollect -> startFragmentDrop();  // 下发掉落计划
            case DisasterImpact -> startDisaster();      // 下发灾难参数
            case Rest -> syncBuildingHP();                // 校正建筑 HP
            case Upgrade -> pushTalentOptions();          // 下发天赋 3 选 1
        }
    }
}
```

### 阶段流转图

```
Preview (5s)
    │  选灾难 + 生成碎片掉落计划
    ▼
FragmentCollect (15s)
    │  下发掉落计划，双方各自模拟物理掉落
    │  碎片接住 → 服务器仲裁
    ▼
DisasterPreview (5s)
    │  灾害方向指示，玩家返回建筑区域
    ▼
Build (20s)
    │  合成材料 + 建筑放置（服务器验证）
    ▼
DisasterImpact (20s)
    │  灾难渐进入侵（确定性时间轴）
    │  服务器计算伤害 → 下发 HP
    │  建筑受损 → 服务器判定摧毁
    ▼
Rest (10s)
    │  建筑HP校正同步
    │  章节结束恢复HP
    ▼
Upgrade (15s)
    │  天赋 3 选 1（服务器推送选项）
    │  双方选择完毕 → 下一轮 Preview
    ▼
(循环 36 轮)
```

### GamePhase 枚举

```java
public enum GamePhase {
    Preview,           // ① 预告（5秒）
    FragmentCollect,   // ② 碎片收集（15秒）
    DisasterPreview,   // ③ 灾害预告（5秒）
    Build,             // ④ 建造（20秒）
    DisasterImpact,    // ⑤ 灾害冲击（20秒）
    Rest,              // ⑥ 修整（10秒）
    Upgrade,           // ⑦ 升级（15秒）
}
```
