## 一、技术栈版本选型

### 1.1 版本总览

| 组件 | 版本 | 类型 | 说明 |
|------|------|------|------|
| Java | **21** (LTS) | JDK | 2023-09 发布，3 年生态验证，Spring Boot 4.x 最低要求 |
| Spring Boot | **4.1.0** | 框架 | 2026-06 发布，当前唯一长期维护的生产线 |
| MariaDB | **11.4** (LTS) | 数据库 | 2024-05 发布，2 年生产验证，社区支持至 2029-05 |
| Docker | **27.x+** | 容器 | Mac Linux 测试服务器用 |
| Docker Compose | **v2** | 编排 | Mac Linux 测试服务器用 |
| Maven | **3.9.x** | 构建 | Win 开发机用 |
| MariaDB JDBC | **3.4.1** | 驱动 | 官方 JDBC 驱动 |

### 1.2 选型理由

#### Java 21 LTS

| 维度 | Java 21 | Java 25 | Java 17 |
|------|---------|---------|---------|
| 发布时间 | 2023-09 | 2025-09 | 2021-09 |
| 生态成熟度 | ✅ 3 年充分验证 | ⚠️ 不到 1 年 | ✅ 5 年但功能老旧 |
| Virtual Threads | ✅ GA（性能提升） | ✅ GA | ❌ 无 |
| Spring Boot 4.1 兼容 | ✅ 完整支持 | ✅ 支持 | ✅ 最低要求 |
| 风险 | 低 | 中（部分库未适配） | 低但技术债 |

**结论**：Java 21 是当前最稳定且功能充分的选择。

#### Spring Boot 4.1.0

当前 Spring Boot 版本格局（2026-08）：

| 版本 | 状态 | 说明 |
|------|------|------|
| 3.5.x | ❌ EOL (2026-06) | 3.x 系列终结，不再有安全补丁 |
| 4.0.x | ⚠️ 2026-12 EOL | 仅剩 4 个月维护期，不适合新项目 |
| 4.1.x | ✅ 当前稳定 | 2026-06 发布，预期维护至 2027-06+ |

**结论**：没有"更老更稳"的选项。3.5.x 已 EOL，4.0.x 即将 EOL。4.1.x 是新项目唯一可行选择。基于 Spring Framework 7.0（2025-11 发布，已运行 9 个月），核心框架已充分验证。

**稳定策略**：锁定 `4.1.0` 具体版本号，不用 SNAPSHOT。等待 `4.1.1+` 补丁发布后再升级。

#### MariaDB 11.4 LTS

| 维度 | MariaDB 11.4 | MariaDB 11.8 | MariaDB 12.3 |
|------|-------------|-------------|-------------|
| 发布时间 | 2024-05 | 2025-06 | 2026-05 |
| 社区支持至 | **2029-05** | 2028-06 | TBC |
| 补丁版本数 | 12 个（11.4.12） | 8 个（11.8.8） | 2 个（12.3.2） |
| 生产验证 | ✅ **2 年+** | ✅ 1 年 | ⚠️ 3 个月 |
| Docker 镜像 | ✅ 官方稳定 | ✅ 官方稳定 | ⚠️ 较新 |

**结论**：MariaDB 11.4 LTS 是当前最稳定的数据库选择。2 年生产验证、12 个补丁版本、支持至 2029-05。

### 1.3 版本锁定策略

| 组件 | Win 开发机 | Mac Linux 测试服务器 |
|------|-----------|---------------------|
| Java | JDK 21（直装） | Docker 镜像 `eclipse-temurin:21-jre-jammy` |
| Spring Boot | Maven 4.1.0（pom.xml） | 同左（git pull 同步） |
| MariaDB | MariaDB 11.4（直装） | Docker 镜像 `mariadb:11.4` |
| Maven | 3.9.x（直装） | Docker 镜像 `maven:3.9-eclipse-temurin-21`（构建阶段） |

> **关键原则**：两台机器的 Java/MariaDB 大版本完全一致，避免环境差异导致的"在我机器上能跑"问题。

## 二、双机器环境架构

### 2.1 硬件拓扑

```
┌──────────────────────────────────────────────────────┐
│  Win (开发机) — 不用 Docker                            │
│                                                      │
│  · 直装: JDK 21 + Maven 3.9 + MariaDB 11.4           │
│  · IDE: IntelliJ IDEA / VS Code                      │
│  · Unity 客户端代码 (Client/)                          │
│  · Java 服务端代码 (Server/)                           │
│                                                      │
│  本地调试:                                              │
│    · MariaDB 运行在 localhost:3306                    │
│    · Spring Boot 运行在 localhost:8080               │
│    · Unity 客户端连接 ws://127.0.0.1:8080/game        │
│                                                      │
│  测试时: 运行 Unity 客户端 → 连接 Mac Linux 服务器       │
└───────────────────────┬──────────────────────────────┘
                        │ 局域网 (同一网段)
                        ▼
┌──────────────────────────────────────────────────────┐
│  Mac (测试服务器)                                      │
│                                                      │
│  ┌────────────────────────────────────────────┐      │
│  │  Linux 虚拟机 (Ubuntu Server)               │      │
│  │                                            │      │
│  │  · Docker Engine                           │      │
│  │  · MariaDB 11.4 容器 (Port 3306, 内部)       │      │
│  │  · GameServer 容器 (Port 8080, 对外)         │      │
│  │                                            │      │
│  │  代码来源: git pull from remote repo        │      │
│  │  更新方式: git pull && docker compose up     │      │
│  └───────────────────────┬────────────────────┘      │
│                          │                             │
│  测试时: Mac 本机运行 Unity 客户端 → 连接 Linux 服务器    │
└──────────────────────────────────────────────────────┘
```

### 2.2 环境分工

| 机器 | 角色 | 环境方式 | 运行内容 |
|------|------|---------|---------|
| **Win** | 开发 + 本地调试 | 直装 JDK + Maven + MariaDB | 代码编写、IDE 内运行 Spring Boot 调试、Unity 客户端 |
| **Mac** | 测试服务器 | Linux 虚拟机 + Docker | `git pull` + `docker compose up`，对外暴露 8080 |
| **Win** | 测试客户端 A | Unity 客户端 | 连接 Mac Linux 的 `ws://<mac-ip>:8080/game` |
| **Mac** | 测试客户端 B | Unity 客户端 | 连接 Linux 的 `ws://127.0.0.1:8080/game` |

### 2.3 代码同步流程

```
Win 开发机                     Git 远程仓库                  Mac Linux 虚拟机
    │                               │                              │
    │  本地开发 + 测试通过             │                              │
    │  git push                     │                              │
    ├──────────────────────────────►│                              │
    │                               │                              │
    │                               │  git pull                    │
    │                               ├─────────────────────────────►│
    │                               │                              │
    │                               │  docker compose up --build   │
    │                               │  ──────────────────────────► │ (重建镜像并启动)
    │                               │                              │
    │  WebSocket 连接 :8080          │                              │
    ├──────────────────────────────────────────────────────────────►│
```

## 三、Win 开发机环境搭建

### 3.1 需要安装的软件

| 软件 | 版本 | 用途 | 下载 |
|------|------|------|------|
| JDK | 21 LTS | 编译运行 Spring Boot | Adoptium / Oracle |
| Maven | 3.9.x | 依赖管理与打包 | maven.apache.org |
| MariaDB | 11.4.x | 本地数据库 | mariadb.org/download |
| IntelliJ IDEA | Ultimate / Community | Java 开发 IDE | jetbrains.com |
| Git | latest | 版本控制 + 代码推送到 Mac | git-scm.com |

> Win 上**不装 Docker**。数据库和 Java 应用直接安装运行，IDE 内启动调试。

### 3.2 Win 环境变量配置

```powershell
# 系统环境变量（PowerShell 管理员执行）

# JDK 21
setx JAVA_HOME "C:\Program Files\Java\jdk-21" /M
setx PATH "%PATH%;%JAVA_HOME%\bin" /M

# Maven
setx MAVEN_HOME "C:\apache-maven-3.9.x" /M
setx PATH "%PATH%;%MAVEN_HOME%\bin" /M

# 验证
java -version
mvn -version
```

### 3.3 Win MariaDB 配置

安装 MariaDB 11.4 时设置：
- 端口: `3306`
- root 密码: 自定义
- 字符集: `utf8mb4`

创建项目数据库和用户：

```sql
CREATE DATABASE dualenigma CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'dualenigma'@'localhost' IDENTIFIED BY 'dualenigma_dev';
GRANT ALL PRIVILEGES ON dualenigma.* TO 'dualenigma'@'localhost';
FLUSH PRIVILEGES;
```

导入初始化脚本：

```bash
mysql -u root -p < src\main\resources\db\schema.sql
```

### 3.4 Win Spring Boot 本地运行

在 IntelliJ IDEA 中：
1. 打开 `Server/` 项目
2. Maven 自动导入依赖
3. 运行 `GameServerApplication.java`（Main 类）
4. Spring Boot 启动在 `localhost:8080`

或命令行运行：

```bash
cd D:\PersonProjects\DualEnigma\Server
mvn spring-boot:run
```

### 3.5 Win 本地连接地址

| 用途 | 地址 |
|------|------|
| MariaDB | `jdbc:mariadb://localhost:3306/dualenigma` |
| GameServer | `ws://127.0.0.1:8080/game` |
| Unity 客户端 → 本地服务器 | `ws://127.0.0.1:8080/game` |

## 四、Mac Linux 虚拟机环境搭建

### 4.1 虚拟机准备

| 项目 | 建议 |
|------|------|
| 虚拟机软件 | VMware Fusion / Parallels / UTM |
| Linux 发行版 | Ubuntu Server 24.04 LTS |
| CPU | 2 核+ |
| 内存 | 4GB+ |
| 磁盘 | 20GB+ |
| 网络 | **桥接模式**（获得与 Mac 同网段独立 IP） |

> 桥接网络最简单——虚拟机有独立 IP（如 `192.168.1.110`），Win 和 Mac 都通过该 IP 直连，无需端口转发。

### 4.2 Linux 虚拟机内安装 Docker

```bash
# SSH 登录 Linux 虚拟机
ssh user@<linux-vm-ip>

# 安装 Docker
curl -fsSL https://get.docker.com | sh

# 将当前用户加入 docker 组（免 sudo）
sudo usermod -aG docker $USER
newgrp docker

# 验证
docker --version
docker compose version
```

### 4.3 Linux 虚拟机部署 GameServer

**首次部署**：

```bash
# 1. 克隆代码
git clone <repo-url> ~/dualenigma
cd ~/dualenigma/Server

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env，设置密码

# 3. 启动（使用 prod 配置，不暴露 3306）
docker compose -f docker-compose.yml -f docker-compose.prod.yml --env-file .env up -d --build

# 4. 确认运行
docker compose ps

# 5. 查看日志
docker compose logs -f gameserver
```

**日常更新（Win push 代码后）**：

```bash
cd ~/dualenigma
git pull
cd Server
docker compose -f docker-compose.yml -f docker-compose.prod.yml --env-file .env up -d --build
docker compose logs -f gameserver
```

### 4.4 测试连接地址

| 客户端位置 | 服务器地址 |
|-----------|----------|
| Win → Mac Linux 测试 | `ws://<linux-vm-ip>:8080/game` |
| Mac → Linux 本机测试 | `ws://<linux-vm-ip>:8080/game` |

> 建议在 Unity 客户端的 `NetworkConfig` 中做成可配置字段，方便切换连接地址。

### 4.5 连通性验证

```bash
# 1. Linux 虚拟机内验证
curl http://localhost:8080

# 2. Mac 宿主机验证（桥接网络）
curl http://<linux-vm-ip>:8080

# 3. Win 验证（局域网）
curl http://<linux-vm-ip>:8080
```

## 六、Docker 配置文件（Mac Linux 测试服务器用）

### 6.1 docker-compose.yml

```yaml
# Server/docker-compose.yml
# Mac Linux 虚拟机测试环境：GameServer + MariaDB

services:
  mariadb:
    image: mariadb:11.4
    container_name: dualenigma-db
    restart: unless-stopped
    environment:
      MARIADB_ROOT_PASSWORD: ${DB_ROOT_PASSWORD}
      MARIADB_DATABASE: ${DB_NAME}
      MARIADB_USER: ${DB_USER}
      MARIADB_PASSWORD: ${DB_PASSWORD}
      TZ: Asia/Shanghai
    ports:
      - "3306:3306"
    volumes:
      - mariadb_data:/var/lib/mysql
      - ./src/main/resources/db/schema.sql:/docker-entrypoint-initdb.d/01-schema.sql:ro
    networks:
      - dualenigma-net
    healthcheck:
      test: ["CMD-SHELL", "mariadb-admin ping -h localhost -u root -p${DB_ROOT_PASSWORD}"]
      interval: 10s
      timeout: 5s
      retries: 5

  gameserver:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: dualenigma-server
    restart: unless-stopped
    depends_on:
      mariadb:
        condition: service_healthy
    environment:
      SPRING_PROFILES_ACTIVE: ${SPRING_PROFILE:-dev}
      DB_HOST: mariadb
      DB_PORT: 3306
      DB_NAME: ${DB_NAME}
      DB_USER: ${DB_USER}
      DB_PASSWORD: ${DB_PASSWORD}
      TZ: Asia/Shanghai
    ports:
      - "8080:8080"
    networks:
      - dualenigma-net

volumes:
  mariadb_data:
    driver: local

networks:
  dualenigma-net:
    driver: bridge
```

### 6.3 Dockerfile

```dockerfile
# Server/Dockerfile
# 多阶段构建：构建层 + 运行层分离

# ─── 构建阶段 ───
FROM maven:3.9-eclipse-temurin-21 AS builder

WORKDIR /build
COPY pom.xml .
RUN mvn dependency:go-offline -B

COPY src ./src
RUN mvn clean package -DskipTests -B

# ─── 运行阶段 ───
FROM eclipse-temurin:21-jre-jammy

WORKDIR /app

COPY --from=builder /build/target/*.jar app.jar

EXPOSE 8080

ENTRYPOINT ["java", "-jar", "app.jar"]
```

## 八、数据库初始化脚本

```sql
-- Server/src/main/resources/db/schema.sql
-- MariaDB 11.4 LTS 初始化脚本（Win + Mac Linux 共用）

CREATE DATABASE IF NOT EXISTS dualenigma CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

USE dualenigma;

-- ─── 账号表 ───
CREATE TABLE IF NOT EXISTS player_account (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    username        VARCHAR(64) NOT NULL UNIQUE,
    password_hash   VARCHAR(255) NOT NULL,
    display_name    VARCHAR(64) NOT NULL,
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    last_login_at   DATETIME NULL,
    INDEX idx_username (username)
) ENGINE=InnoDB;

-- ─── 房间表 ───
CREATE TABLE IF NOT EXISTS game_room (
    id              VARCHAR(16) PRIMARY KEY,          -- roomCode
    player0_id      BIGINT NULL,                      -- 水人账号 ID
    player1_id      BIGINT NULL,                      -- 火人账号 ID
    status          ENUM('waiting','playing','finished','abandoned') NOT NULL DEFAULT 'waiting',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    started_at      DATETIME NULL,
    ended_at        DATETIME NULL,
    INDEX idx_status (status),
    INDEX idx_player0 (player0_id),
    INDEX idx_player1 (player1_id)
) ENGINE=InnoDB;

-- ─── 游戏进度表（每局一条，36 轮更新） ───
CREATE TABLE IF NOT EXISTS game_progress (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    room_id         VARCHAR(16) NOT NULL,
    chapter         INT NOT NULL DEFAULT 1,           -- 当前章节 (1-3)
    section         INT NOT NULL DEFAULT 1,           -- 当前节 (1-4)
    round           INT NOT NULL DEFAULT 1,           -- 当前轮 (1-3)
    current_phase   VARCHAR(32) NOT NULL DEFAULT 'Preview',
    phase_end_time  DATETIME NULL,                    -- 阶段结束时间
    score           INT NOT NULL DEFAULT 0,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_room (room_id)
) ENGINE=InnoDB;

-- ─── 玩家运行时状态表（每局每玩家一条） ───
CREATE TABLE IF NOT EXISTS player_state (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    room_id         VARCHAR(16) NOT NULL,
    player_id       TINYINT NOT NULL,                 -- 0=Aqua, 1=Ignis
    account_id      BIGINT NOT NULL,
    hp              INT NOT NULL DEFAULT 100,
    shelter_energy  FLOAT NOT NULL DEFAULT 100.0,
    pos_x           FLOAT NOT NULL DEFAULT 0.0,
    pos_y           FLOAT NOT NULL DEFAULT 0.0,
    velocity_x      FLOAT NOT NULL DEFAULT 0.0,
    velocity_y      FLOAT NOT NULL DEFAULT 0.0,
    anim_state      VARCHAR(16) NOT NULL DEFAULT 'Idle',
    facing          BOOLEAN NOT NULL DEFAULT TRUE,
    carried_fragments JSON NULL,                      -- [0,0,1] 碎片类型列表
    INDEX idx_room_player (room_id, player_id)
) ENGINE=InnoDB;

-- ─── 建筑状态表 ───
CREATE TABLE IF NOT EXISTS building_state (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    room_id         VARCHAR(16) NOT NULL,
    building_id     INT NOT NULL,                     -- 游戏内建筑 ID
    building_type   INT NOT NULL,
    material        INT NOT NULL,
    grid_x          INT NOT NULL,
    grid_y          INT NOT NULL,
    current_hp      FLOAT NOT NULL,
    max_hp          FLOAT NOT NULL,
    placed_by       TINYINT NOT NULL,                -- 放置者 playerId
    INDEX idx_room (room_id),
    UNIQUE KEY uk_room_building (room_id, building_id)
) ENGINE=InnoDB;

-- ─── 碎片状态表 ───
CREATE TABLE IF NOT EXISTS fragment_state (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    room_id         VARCHAR(16) NOT NULL,
    fragment_id     INT NOT NULL,
    fragment_type   TINYINT NOT NULL,                 -- 0=冰晶, 1=熔岩, 2=岩石
    pos_x           FLOAT NOT NULL,
    pos_y           FLOAT NOT NULL,
    state           VARCHAR(16) NOT NULL DEFAULT 'Falling',  -- Falling/Collected/Despawned
    drop_time       FLOAT NOT NULL,
    INDEX idx_room (room_id),
    INDEX idx_room_state (room_id, state)
) ENGINE=InnoDB;

-- ─── 天赋选择记录表 ───
CREATE TABLE IF NOT EXISTS talent_record (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    room_id         VARCHAR(16) NOT NULL,
    player_id       TINYINT NOT NULL,
    talent_id       INT NOT NULL,
    global_round    INT NOT NULL,                    -- 第几轮选择 (1-36)
    selected_at     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_room_player (room_id, player_id)
) ENGINE=InnoDB;

-- ─── 技能状态表 ───
CREATE TABLE IF NOT EXISTS skill_state (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    room_id         VARCHAR(16) NOT NULL,
    player_id       TINYINT NOT NULL,
    skill_id        INT NOT NULL,
    cooldown_remaining FLOAT NOT NULL DEFAULT 0.0,
    use_count       INT NOT NULL DEFAULT 0,
    INDEX idx_room_player (room_id, player_id)
) ENGINE=InnoDB;

-- ─── 灾难状态表 ───
CREATE TABLE IF NOT EXISTS disaster_state (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    room_id         VARCHAR(16) NOT NULL,
    disaster_id     INT NOT NULL,
    difficulty_mult FLOAT NOT NULL,
    random_seed     BIGINT NOT NULL,
    elapsed_time    FLOAT NOT NULL DEFAULT 0.0,
    is_active       BOOLEAN NOT NULL DEFAULT FALSE,
    INDEX idx_room (room_id)
) ENGINE=InnoDB;

-- ─── 对局结算表 ───
CREATE TABLE IF NOT EXISTS game_result (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    room_id         VARCHAR(16) NOT NULL,
    is_victory      BOOLEAN NOT NULL,
    player0_alive   BOOLEAN NOT NULL,
    player1_alive   BOOLEAN NOT NULL,
    final_score     INT NOT NULL,
    duration_sec    INT NOT NULL,
    ended_at        DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_room (room_id)
) ENGINE=InnoDB;
```

### 8.1 表关系概览

```
player_account (1) ──── (N) game_room (player0_id / player1_id)
                                │
                    ┌───────────┼───────────────┐
                    │           │               │
            game_progress   player_state    game_result
                    │           │
                    │     ┌─────┼─────┐─────┐
                    │     │     │     │     │
            building_state │ skill_state  talent_record
                            │
                       fragment_state
                            │
                       disaster_state
```

### 8.2 持久化策略

| 数据 | 写入时机 | 读取时机 | 说明 |
|------|---------|---------|------|
| player_account | 注册时 | 登录时 | 永久存储 |
| game_room | 创建房间时 | 匹配时 | 对局结束保留记录 |
| game_progress | 每阶段切换 | 重连时 | 断线恢复用 |
| player_state | 每 10Hz Tick | 重连时 | 内存为主，定期刷盘 |
| building_state | 放置/摧毁时 | 重连时 | 事件驱动写入 |
| fragment_state | 掉落/收集时 | 重连时 | 事件驱动写入 |
| talent_record | 选择时 | 重连时 | 事件驱动写入 |
| skill_state | 释放时 | 重连时 | 事件驱动写入 |
| disaster_state | 灾难开始时 | 重连时 | 事件驱动写入 |
| game_result | 对局结束时 | 历史查询 | 永久存储 |

> **核心原则**：运行时状态在内存中维护，定期和事件驱动写入数据库。断线重连时从数据库读取快照恢复。
