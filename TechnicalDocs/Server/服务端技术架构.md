## 一、系统概述

### 1.1 架构决策

采用 **Java 服务器权威 + 双 Unity 客户端** 架构，取代原 Host-Client 模式。

| 维度 | 原 Host-Client | 现 Java 服务器权威 |
|------|---------------|-------------------|
| 权威方 | 房主 Unity 实例 | 独立 Java 服务器进程 |
| 网络拓扑 | P2P（Host 兼服务器） | 星型（服务器居中） |
| 协议 | TCP + UDP 混合 | WebSocket（TCP） |
| 序列化 | Protobuf | JSON |
| 客户端复杂度 | 高（Host 需跑权威逻辑） | 低（仅渲染 + 输入 + 预测） |
| 防作弊 | Host 权威（房主可作弊） | 服务器权威（客户端无法作弊） |

### 1.2 项目约束

| 约束 | 说明 |
|------|------|
| 并发模型 | 单房间 2 人，服务器可同时运行多个房间 |
| 单局时长 | 36 关 × 90s ≈ 54 分钟 |
| 单轮结构 | 7 阶段 90s（预告→碎片收集→灾害预告→建造→灾害冲击→修整→升级） |
| 帧率 | 逻辑帧 20Hz（50ms），高频状态同步 20Hz |
| 断线处理 | 30 秒重连窗口 + AI 接管 + 120 秒超时 |
| 部署 | 单进程多线程，后续可扩展为分布式 |

### 1.3 技术选型

| 维度 | 选择 | 理由 |
|------|------|------|
| 语言 | Java 17 (LTS) | 生态成熟，WebSocket 支持完善 |
| 框架 | Spring Boot 3.x + spring-boot-starter-websocket | 内置 WebSocket 支持，自动配置，快速启动 |
| 序列化 | Jackson JSON | 2 人游戏数据量极小（~3KB/s），JSON 可读性好，调试方便 |
| 构建工具 | Maven | 标准化依赖管理 |
| 心跳 | WebSocket Ping/Pong + 应用层心跳 | 双重检测 |

## 三、服务器参数

### 3.1 核心参数

| 参数 | 值 | 说明 |
|------|------|------|
| WebSocket 端口 | 8080 | Spring Boot 默认 |
| 逻辑帧率 | 20Hz (50ms) | GameTickScheduler |
| 高频状态转发频率 | 20Hz | 收到即转发 |
| 中频状态下发频率 | 10Hz | 服务器 Tick 中下发 |
| 心跳间隔 | 1s | 应用层心跳 |
| 心跳超时 | 5s | 判定断线 |
| 重连窗口 | 30s | AI 接管前等待 |
| 最终超时 | 120s | 游戏结束 |
| 插值缓冲 | 20ms | 局域网低延迟 |
| 校正阈值 | 0.5 格 | 角色位置校正 |

### 3.2 application.yml

```yaml
server:
  port: 8080

spring:
  application:
    name: dualenigma-game-server

# 游戏服务器自定义配置
dualenigma:
  game:
    tick-rate: 20              # 逻辑帧率 (Hz)
    tick-interval-ms: 50       # 逻辑帧间隔 (ms)
    high-freq-rate: 20         # 高频状态同步频率 (Hz)
    mid-freq-rate: 10          # 中频状态同步频率 (Hz)
    heartbeat-interval: 1000   # 心跳间隔 (ms)
    heartbeat-timeout: 5000    # 心跳超时 (ms)
    reconnect-window: 30000    # 重连窗口 (ms)
    ai-takeover-timeout: 30000 # AI 接管超时 (ms)
    final-timeout: 120000      # 最终超时 (ms)
    max-rooms: 100             # 最大并发房间数
```

### 3.3 带宽估算

| 消息类型 | 单条大小 | 频率 | 双向带宽 |
|----------|---------|------|---------|
| 高频状态 ×2 | ~120 bytes | 20Hz × 2 | ~4.8 KB/s |
| 中频状态 | ~200 bytes | 10Hz | ~2.0 KB/s |
| 关键事件 | ~150 bytes | 峰值 ~5/s | ~0.75 KB/s |
| 心跳 ×2 | ~40 bytes | 1Hz × 2 | ~0.08 KB/s |
| **总计** | — | — | **~8 KB/s** |

> WebSocket + JSON 比二进制协议开销大，但 2 人游戏总量极小，完全可接受。

## 四、实施路线图

### Phase 0: 服务器骨架（验证通信链路）

| 任务 | 产出 |
|------|------|
| Maven 项目搭建 | `pom.xml` + Spring Boot 启动 |
| WebSocket 端点 | 客户端能连接、断开 |
| 消息编解码 | JSON ↔ Java 对象 |
| 房间管理 | 2 人匹配、房间创建 |
| 心跳检测 | 断线感知 |

### Phase 1: 阶段同步（最小可玩验证）

| 任务 | 产出 |
|------|------|
| 服务器 GameStateMachine | 7 阶段计时器自动流转 |
| PhaseChange 同步 | 双客户端同步收到阶段切换 |
| 客户端被动接收 | 客户端不再自跑计时器 |

### Phase 2: 角色位置同步

| 任务 | 产出 |
|------|------|
| C2S/S2C_HighFreqState | 角色位置双向同步 |
| 客户端本地预测 | 本地角色即时响应 |
| 远程角色插值 | 远程角色平滑移动 |

### Phase 3: 核心玩法同步

| 任务 | 产出 |
|------|------|
| 碎片掉落计划同步 | 双方碎片同步掉落 |
| 碎片接住仲裁 | 服务器判定碎片归属 |
| 灾难选型+种子同步 | 双方灾难效果一致 |
| 建筑放置+摧毁同步 | 双方建筑状态一致 |
| HP/能量同步 | 服务器权威 HP |

### Phase 4: 辅助系统

| 任务 | 产出 |
|------|------|
| 天赋选择同步 | 双方天赋选择可见 |
| 技能释放同步 | 技能视觉效果+机制判定 |
| 断线重连 | 全量快照恢复 |
| AI 接管 | 断线玩家 AI 控制 |
