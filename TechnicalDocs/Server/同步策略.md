## 一、同步分层

| 层级 | 内容 | 频率 | 服务器处理 | 消息类型 |
|------|------|------|----------|---------|
| 高频状态 | 角色位置/速度/动画/朝向 | 20Hz | 接收 → 立即转发 | C2S/S2C_HighFreqState |
| 中频状态 | HP/能量/碎片位置 | 10Hz | 服务器计算 → 下发 | S2C_MidFreqState |
| 关键事件 | 碎片接住/建筑放置/技能释放 | 事件驱动 | 服务器判定 → 广播结果 | C2S_* / S2C_*Result |
| 阶段切换 | 7 阶段流转 | 7次/轮 | 服务器驱动 → 广播 | S2C_PhaseChange |

## 二、高频状态同步

### 2.1 流程

```
客户端A (20Hz):
  1. 采集本地角色 position/velocity/animState/facing
  2. 发送 C2S_HighFreqState → 服务器

服务器 (收到后立即转发):
  1. 更新 PlayerState[0] 的位置缓存
  2. 转发 S2C_HighFreqState(playerId=0) → 客户端B

客户端B (收到后):
  1. 放入插值缓冲区（20ms 缓冲）
  2. 在两个位置快照间线性插值
  3. 渲染插值结果
```

### 2.2 客户端本地预测

```
本地角色移动:
  1. 玩家输入 → 本地立即应用移动（预测）
  2. 发送 C2S_HighFreqState 给服务器
  3. 服务器转发给对方

远程角色渲染:
  1. 接收 S2C_HighFreqState
  2. 放入插值缓冲区（20ms）
  3. 在两个位置快照间线性插值
  4. 渲染插值结果
```

### 2.3 参数

| 参数 | 值 | 说明 |
|------|------|------|
| 发送频率 | 20Hz (50ms) | 客户端发送 |
| 转发延迟 | <1ms | 服务器收到即转发 |
| 插值缓冲 | 20ms | 局域网低延迟 |
| 插值方法 | 线性插值 | `Vector2.Lerp` |
| 外推限制 | 100ms | 超过缓冲区最新包时最多外推 100ms |

## 三、中频状态同步

### 3.1 流程

```
服务器 (10Hz Tick):
  1. 遍历两个 PlayerState，计算 HP/能量
  2. 遍历场上活跃碎片，收集位置
  3. 打包为 S2C_MidFreqState
  4. 广播给双方

客户端 (收到后):
  1. 直接更新本地 HP/能量显示
  2. 更新碎片位置缓存
```

### 3.2 同步内容

| 字段 | 类型 | 说明 |
|------|------|------|
| playerId | int | 玩家 ID |
| hp | int | 当前生命值（服务器权威） |
| shelterEnergy | int | 庇护能量值（0-100） |
| carriedFragments | int[] | 携带的碎片类型列表 |

### 3.3 关键原则

- **HP 为服务器唯一权威**：客户端不自行扣血，只从中频状态包接收
- **能量服务器计算**：基于双方位置距离计算能量增减
- **碎片位置同步**：场上活跃碎片的位置由服务器 10Hz 下发

## 四、关键事件同步

### 4.1 碎片接住

```
客户端A --C2S_FragmentCaught(fragId=42)--> 服务器

服务器:
  1. ConflictResolver.onCatch(42, playerId=0, catchTime)
  2. 若结果非 null → 判定完成
  3. 若结果为 null → 等待客户端B 或超时

  情况A: 客户端B 也发了 C2S_FragmentCaught(42)
    → ConflictResolver 判定同时接住 ×3
    → 广播 S2C_FragmentResult(fragId=42, multiplier=3)

  情况B: 100ms 内客户端B 没发
    → checkTimeout 判定单人接住 ×1
    → 发送 S2C_FragmentResult(fragId=42, playerId=0, multiplier=1)

客户端 (收到 S2C_FragmentResult):
  1. 执行碎片收集逻辑（添加碎片到背包）
  2. 播放收集特效
  3. 更新倍率显示
```

### 4.2 碎片掉落计划

```
服务器 (Preview 阶段):
  1. DisasterSelector.select() → 选灾难 + 生成种子
  2. FragmentPlanner.generatePlan() → 生成掉落计划
  3. 广播 S2C_DisasterStart(type, seed, params)
  4. 广播 S2C_FragmentDropPlan(plan[])

客户端 (收到后):
  1. 缓存掉落计划
  2. FragmentCollect 阶段开始时执行 ExecuteDropPlan
  3. 双方各自模拟碎片物理掉落（使用相同种子，轨迹一致）
```

### 4.3 建筑放置

```
客户端A --C2S_BuildingPlace(type, material, gridX, gridY)--> 服务器

服务器:
  1. BuildingManager.place() → 验证网格占用 → 创建建筑
  2. 广播 S2C_BuildingUpdate(action=place, building={...})

客户端 (收到后):
  1. 在本地网格创建建筑实例
  2. 播放放置特效
```

### 4.4 建筑摧毁

```
服务器 (DisasterImpact 阶段):
  1. DamageCalculator.calculateBuildingDamage() → 每 Tick 累积伤害
  2. 建筑 HP ≤ 0 → BuildingManager 标记摧毁
  3. 广播 S2C_BuildingUpdate(action=destroy, buildingId=X)

客户端 (收到后):
  1. 移除建筑实例
  2. 播放摧毁特效
```

### 4.5 建筑修整同步

```
服务器 (Rest 阶段):
  1. BuildingManager.syncBuildingHP() → 获取所有建筑当前 HP
  2. 广播 S2C_BuildingUpdate(action=sync, buildings=[...])

客户端 (收到后):
  1. 校正所有建筑 HP（消除浮点误差）
  2. 更新建筑显示
```

### 4.6 技能释放

```
客户端A --C2S_SkillActivate(skillId, targetPos)--> 服务器

服务器:
  1. 验证技能冷却/可用次数
  2. 执行机制判定（伤害/冻结等）
  3. 广播 S2C_SkillResult(skillId, playerId, effects[])

客户端 (收到后):
  1. 本地播放技能视觉特效（若未提前预测播放）
  2. 应用机制效果（伤害/冻结等）
```

> 技能视觉效果可由客户端在发送 `C2S_SkillActivate` 后立即本地播放（减少延迟感），机制效果等待服务器判定结果。

### 4.7 天赋选择

```
服务器 (Upgrade 阶段):
  1. TalentPool.rollOptions() → 生成 3 选 1
  2. 发送 S2C_TalentOptions(options[]) → 双方各自收到

客户端A --C2S_TalentSelect(talentId)--> 服务器

服务器:
  1. 记录天赋选择
  2. 发送 S2C_TalentSelected(playerId=0, talentId) → 客户端B
  3. 双方都选完 → 进入下一轮 Preview
```

## 五、阶段同步

### 5.1 流程

```
服务器 GameStateMachine:
  1. onTick 检查 phaseEndTime
  2. 时间到 → nextPhase()
  3. setPhase() → 广播 S2C_PhaseChange(phase, durationMs, phaseEndTime)

客户端 (收到 S2C_PhaseChange):
  1. 停止本地计时器
  2. 设置当前阶段
  3. 用 phaseEndTime 校正本地计时器
  4. 触发阶段进入逻辑（UI 切换、碎片开始掉落等）
```

### 5.2 阶段进入触发

| 阶段 | 服务器动作 | 下发消息 |
|------|----------|---------|
| Preview | 选灾难 + 生成碎片计划 | S2C_DisasterStart + S2C_FragmentDropPlan |
| FragmentCollect | 下发掉落计划（若 Preview 未下发） | S2C_FragmentDropPlan |
| DisasterPreview | 无额外动作 | — |
| Build | 无额外动作 | — |
| DisasterImpact | 启动灾难模拟 | — (参数已在 Preview 下发) |
| Rest | 同步建筑 HP | S2C_BuildingUpdate(action=sync) |
| Upgrade | 推送天赋 3 选 1 | S2C_TalentOptions |

### 5.3 时间对齐

客户端使用 `phaseEndTime` 校正本地计时器：

```
本地剩余时间 = phaseEndTime - 当前服务器时间
```

> 客户端通过 `S2C_HeartbeatAck.serverTimestamp` 估算服务器时间（`serverTime = 本地时间 - RTT/2`）。
