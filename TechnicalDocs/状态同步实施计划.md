# 状态同步实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 打通双人联机对局内的状态同步（阶段流转 / 角色位置 / 生命能量 / 碎片掉落与拾取），使双方"同场对局"而非"各玩各的"。

**Architecture:** 服务器权威（阶段计时、碎片掉落计划、拾取判定转发）+ 客户端模拟（自身角色物理本地计算后上报）。复用既有 WebSocket JSON 信封协议 `{type, timestamp, playerId, data}`：高频 20Hz C2S→S2C 直转发，中频 10Hz 服务器快照广播，阶段/掉落计划事件式广播。

**Tech Stack:** Unity 2022.3（C#, EventBus/Singleton/ServiceLocator 既有框架）· Spring Boot 4.1 + Java 21（game-server/network 模块，Jackson 编解码）

---

1. 客户端 `FragmentType` 枚举顺序 `IceCrystal=0, Lava=1, Rock=2`，与服务端 `type` 注释一致，可直接强转。
2. 客户端 `GenerateDropPlan/ExecuteDropPlan` 目前**无任何调用方**（本地掉落未接入流程）——M4 无需禁用本地生成。

6. 双端时钟不可信，剩余时长一律用**消息内差值**（`phaseEndTime - timestamp`）计算，禁止用本地墙钟减服务器墙钟。

/// ============================================================
/// 文件名: RemoteCharacterDriver.cs
/// 创建时间: 2026-08-15
/// 作者: DualEnigma
/// 描述: 远程角色驱动器。订阅 HighFreqStateReceivedEvent，
///       以插值缓冲（默认 100ms）回放对方位置，平滑网络抖动。
///       组件挂在远程角色上（Kinematic 刚体）。
/// ============================================================

using System.Collections.Generic;
using UnityEngine;
using DualEnigma.Framework.Core;
using DualEnigma.Data;
using DualEnigma.Network;

namespace DualEnigma.Character
{
    [RequireComponent(typeof(CharacterController))]
    public class RemoteCharacterDriver : MonoBehaviour
    {
        private struct Sample
        {
            public float Time;
            public Vector2 Position;
        }

        private CharacterController _controller;
        private Rigidbody2D _rb;
        private readonly List<Sample> _buffer = new List<Sample>();
        private float _bufferSec = 0.1f;
        private string _lastAnim = "";
        private bool _lastFacing = true;

        private void Awake()
        {
            _controller = GetComponent<CharacterController>();
            _rb = GetComponent<Rigidbody2D>();

            NetworkConfig config = DataManager.Instance.LoadConfig<NetworkConfig>("NetworkConfig");
            if (config != null) _bufferSec = config.InterpolationBuffer;
        }

        private void OnEnable()
        {
            EventBus.Instance.Subscribe<HighFreqStateReceivedEvent>(OnStateReceived);
        }

        private void OnDisable()
        {
            EventBus.Instance.Unsubscribe<HighFreqStateReceivedEvent>(OnStateReceived);
        }

        private void OnStateReceived(HighFreqStateReceivedEvent e)
        {
            if (_controller == null || e.playerId != _controller.PlayerId) return;

            _buffer.Add(new Sample { Time = Time.time, Position = e.position });
            if (_buffer.Count > 40) _buffer.RemoveAt(0); // ~2s @20Hz 上限，防内存增长

            if (e.animState != _lastAnim)
            {
                _lastAnim = e.animState;
                if (System.Enum.TryParse(_lastAnim, out AnimState anim))
                    _controller.SetNetworkAnimState(anim);
            }

            if (e.facing != _lastFacing)
            {
                _lastFacing = e.facing;
                _controller.SetNetworkFacing(e.facing);
            }
        }

        private void Update()
        {
            if (_buffer.Count < 2 || _rb == null) return;

            float renderTime = Time.time - _bufferSec;

            // 丢弃被追上的过期样本（保留最近 2 个用于插值）
            while (_buffer.Count > 2 && _buffer[1].Time <= renderTime)
                _buffer.RemoveAt(0);

            Sample a = _buffer[0];
            Sample b = _buffer[1];
            float span = b.Time - a.Time;
            float t = span > 0f ? Mathf.Clamp01((renderTime - a.Time) / span) : 1f;

            _rb.position = Vector2.Lerp(a.Position, b.Position, t);
        }
    }
}

> **与同接 pending 机制的交互（重要）**：接收方调用 `OnFragmentCollected(对方ID)` 会进入 100ms 待确认窗口而非立即移除——超时后由 `CompletePendingCollect` 完成并发布事件（playerId=对方 → NetworkGameSync 过滤，不会回发，无回环）。**副作用 ①**：对方碎片在本地延迟 ~100ms+RTT 消失（可接受）。**副作用 ②**：若 100ms 窗口内本地玩家恰好也接住同一碎片，本地会单方面判定"同接×3"而对方不会（判定不对称）——此为 MVP 已知限制，归 M5 服务器权威判定（ConflictResolver）修复。
>
> **可选优化（消除副作用②）**：给 `FragmentSystem` 新增公开方法跳过 pending 直接完成（基于已确认的字段/方法 `_activeFragments`/`_collectedFragmentTypes`/`ReleaseFragment` 编写）：
>
> ```csharp
>         /// <summary>网络同步：对方接住 → 跳过同接判定直接完成收集并移除</summary>
>         public void ForceCollect(int fragmentId, byte playerId)
>         {
>             if (!_activeFragments.TryGetValue(fragmentId, out FragmentController fragment))
>                 return;
>
>             EventBus.Instance.Publish(new Core.FragmentCollectedEvent
>             {
>                 fragmentId = fragmentId,
>                 playerId = playerId,
>                 isJumping = false,
>                 multiplier = 1
>             });
>
>             _collectedFragmentTypes[fragmentId] = fragment.Type;
>             ReleaseFragment(fragmentId);
>         }
> ```
>
> 采用此方案时，上面的分发 case 改调 `ForceCollect(msg.data.fragmentId, (byte)msg.data.playerId)`，并删除两条副作用说明。
