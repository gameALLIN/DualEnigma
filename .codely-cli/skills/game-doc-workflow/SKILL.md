# 游戏策划文档工作流

## 核心原则

**所有文档调整必须同步录入版本记录。** 从源头规避内容错乱、版本混淆、信息追溯困难。

## 两种工作模式

### 设计模式（创意构思阶段）

**触发条件：** 用户说"设计"、"想一想"、"头脑风暴"、"创意"等

**工作方式：**
- 灵活创作，不受固化逻辑束缚
- 充分发挥想象力，发散思维
- 完成框架搭建、内容初稿、方案打磨
- 输出多元化、创新性内容雏形

**文档处理：**
- 新建文档时添加 `> **文档状态**: 设计草案`
- 不强制要求逻辑自洽，允许探索性内容
- 版本记录标记为"新建"或"内容扩充"

### 敲定模式（落地定稿阶段）

**触发条件：** 用户说"敲定"、"定稿"、"确定"、"落实"等

**工作方式：**
- 严守逻辑规范，聚焦内容落地
- 确保全文逻辑自洽、前后连贯
- 杜绝逻辑漏洞、内容冲突、表述混乱
- 校准细节，确保专业性和准确性

**文档处理：**
- 更新文档状态为 `> **文档状态**: 机制定稿` 或 `> **文档状态**: 设计定稿`
- 检查并修复跨文档不一致
- 版本记录标记为"机制定稿"或"内容修订"

## 工作流程

### 1. 修改文档时

```
1. 读取目标文档
2. 执行修改（设计模式或敲定模式）
3. 更新文档头部版本号和日期
4. 同步更新 版本记录.md
5. 检查是否需要更新其他关联文档
```

### 2. 版本记录格式

```markdown
## vX.0 — YYYY-MM-DD 变更标题

### 变更原因
简述为什么要做这次变更。

### 核心变更
| 维度 | 旧版本 | 新版本 |
|------|--------|--------|

### 新增/删除系统
- **新增**：xxx
- **删除**：~~xxx~~

### 文档状态
| 文档 | 状态 | 说明 |
|------|------|------|
```

### 3. 跨文档一致性检查

修改一个文档后，检查以下关联文档是否需要同步：

| 主文档 | 关联文档 |
|--------|----------|
| GDD | 所有子系统设计文档 |
| 双生庇护系统设计 | GDD、技能系统设计 |
| 技能系统设计 | GDD、双生庇护系统设计 |
| 地图设计 | GDD |
| 灾难系统设计 | GDD、双生庇护系统设计 |

## 文档头部规范

每个文档必须包含：

```markdown
> **文档版本**: vX.0  
> **最后更新**: YYYY-MM-DD  
> **文档状态**: 设计草案 | 机制定稿中 | 设计定稿  
> **对应GDD版本**: vX.0  
> **注意**: （可选）特殊说明
```

## 注意事项

- 数值类内容标记为"占位值，待机制敲定后统一调整"
- 暂定内容标记为"暂定"或"待敲定"
- 不要在设计模式下强制要求逻辑完整
- 不要在敲定模式下引入未经验证的新创意
